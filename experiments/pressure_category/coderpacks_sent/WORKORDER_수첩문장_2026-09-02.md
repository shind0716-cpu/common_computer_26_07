# 작업 지시서 — 판독 팩 「수첩 문장」 (2026-09-02)

> 클로드 코드에서 이 파일만 열고 따라가면 된다. **실호출 0.**
> 사전고정은 `PREREG_수첩문장_2026-09-02.md`. **열쇠(`_KEY_S.json`)는 §3 전까지 열지 않는다.**
> 지난 팩(99 에이전트)과 같은 방식이다 — 판정 수를 작게 주고, 답은 파일로 쓴다.

## 0. 어디에 푸나

```
experiments/pressure_category/coderpacks_sent/
  ├ packs/PACK_S_01.md … PACK_S_06.md   6팩 × 수첩 8장 · 문장 299개
  ├ _KEY_S.json                          열쇠 — 봉인
  ├ PACK_HASHES.txt                      동결 해시
  └ tools/  build.py · collect.py · score.py · head.md
```

해시부터 맞춰 둔다.

```bash
cd experiments/pressure_category/coderpacks_sent
python - <<'EOF'
import hashlib,glob,os
have={f"{hashlib.sha256(open(p,'rb').read()).hexdigest()[:12]}  packs/{os.path.basename(p)}"
      for p in glob.glob("packs/PACK_S_*.md")}
want=set(open('PACK_HASHES.txt',encoding='utf-8').read().split('\n'))-{''}
print("일치" if have==want else f"어긋남 {len(want-have)}")
EOF
```

## 1. 왜 이걸 재나 — 한 문단

수첩에 대해 우리가 잰 것은 「재료 사실이 남았나」 하나뿐이다. 그런데 수첩 문장의
절반 이상이 사실이 아니고, 그것이 무엇인지 한 번도 안 봤다. 게다가 보고서 §3-4 가
「500자가 병목」이라고 적고 있는데 **gpt 수첩은 중앙 260자이고 500자를 넘긴 것이 0장**이다.
예산이 남는데 밖이 안 적힌다면 이유는 자리가 아니라 고르기다. 그 나머지를 세는 팩이다.

## 2. 돌리기 — 에이전트 여섯

에이전트 하나가 팩 하나. 모델은 Sonnet. `NN` 만 바꿔 그대로 쓴다.
여섯을 한 번에 띄워도 된다(수첩 8장 · 문장 50개 안팎이라 가볍다).

```
당신은 판독자입니다. 다른 어떤 작업도 하지 마십시오.

1. `coderpacks_sent/packs/PACK_S_NN.md` 를 Read 로 읽으십시오.
2. 그 파일 머리의 지침(갈래 여섯 · 새 내용 · 지킬 것)을 그대로 따르십시오.
3. 수첩 8장의 문장마다 갈래 하나와 새 내용 예/아니오를 판정하십시오.
4. 결과를 Write 로 `coderpacks_sent/packs/OUT_S_NN.md` 에 쓰십시오.

파일 형식 — 수첩마다 이것만. 다른 글자는 넣지 마십시오.

## N-XX
| 번호 | 갈래 | 새 내용 |
|---|---|---|
| s01 | 사실 | 아니오 |
...그 수첩의 마지막 문장까지

갈래는 사실 / 결론 / 되풀이 / 단서 / 지시 / 그밖 중 하나입니다.
근거·설명을 쓰지 마십시오. 길게 쓰면 도중에 잘려 수첩이 통째로 날아갑니다.
최종 답변에는 `쓴 파일: <경로> · 수첩 <개수>` 한 줄만 적으십시오.
```

## 3. 모으기 — 여기까지 열쇠는 닫혀 있다

```bash
python tools/collect.py
```

빠진 수첩이 있으면 **다시 돌릴 팩 번호를 찍어 준다.** 그 팩만 다시 돌린다.
`48/48 · 어긋남 0` 이 되면 `_COLLECTED_S.json` 을 쓴다. 그 전에는 열쇠를 열지 않는다.

## 4. 열쇠 열고 채점

```bash
python tools/score.py
```

**맨 먼저 대조 정답률이 찍힌다.** 팩에 심어 둔 것이 아니라 자연 발생한 128칸이다 —
표식이 그대로 낀 문장은 「사실」로, 「결론:」으로 시작하는 문장은 「결론」으로 나와야 한다.

- **60% 아래면 거기서 멈춘다.** 나머지 표를 읽지 말고 보고한다. 검사에 눈이 하나 없는 것이다.
- 넘으면 갈래 표·라운드 표·사실 몫이 이어서 찍히고 `SCORE_S.md` 를 쓴다.

사전고정 §4 의 예상 여섯(S1~S6)은 그 표를 보고 사람이 판정한다.

## 5. 끝나고

- `SCORE_S.md` · `OUT_S_*.md` 전량 보존. 다시 돌린 팩의 실패본도 지우지 않는다.
- **보고서 §3-4 를 고쳐야 한다.** 「500자가 병목」은 gpt 에서 안 서는 말이고,
  그 문장은 `ALL34_RESULT` §1-2 에서 온 것이라 그쪽에도 정정 줄이 필요하다.
  `ROUNDS` §3 의 평균 글자(하이쿠 404 · 제미나이 438 · gpt 263)가 이미 같은 말을 하고 있었다.
- 색인에 한 줄. type 은 `result`.

## 6. 이 팩이 못 하는 말

사전고정 §6 그대로다 — 문장 쪼개기를 기계가 했고, 조건이 문면에 드러나며,
48장은 594장의 일부이고, 코더가 사람이 아니다.
