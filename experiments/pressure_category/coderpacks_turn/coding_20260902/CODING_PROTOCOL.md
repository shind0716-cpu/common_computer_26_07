# 팩 「돌아섬」 블라인드 판독 규약 (2026-09-02)

> 지위: 작업 규약. 분석은 **사후 탐색**이다.

## 분리

- 코더 둘은 서로 다른 모델 계열의 fresh tool-less 세션이다.
- 각 코더는 공개 팩과 이 규약만 본다.
- `_KEY_T_2026-09-02.json`, 저장소, 다른 코더 출력, 집계, 이전 세션은 보지 않는다.
- 24쌍을 각각 독립으로 읽고 전체에서 뒤집힌 비율을 추정하지 않는다.

## 항목별 판독

1. `same_principle`: `같다` · `다르다` · `모르겠다`.
2. `principle_evidence_before/after`: 각 수첩의 원칙을 보여 주는 짧은 그대로 인용.
3. `answer_relation`: 뒤 수첩이 앞 수첩과 `같은 답` · `다른 답` · `모르겠다` 중 어디에 이르는지.
4. `answer_evidence_before/after`: 각 수첩의 실제 추천 방향을 보여 주는 짧은 그대로 인용.
5. `change_basis`: `answer_relation=다른 답`일 때만 `버렸다` · `다시 해석했다` · `판단 못 하겠다`; 그 밖에는 `null`.
6. `rationale`: 판정 이유 한 줄.
7. `confidence`: 0~1.

가치·원칙 표현이 같다는 이유만으로 답도 같다고 하지 않는다. 반대로 결론이 달라도 같은 원칙을 새 상황에 다시 적용한 것일 수 있다. 추천 방향이 본문에서 판별되지 않으면 억지로 채우지 말고 `모르겠다`를 쓴다.

## 제출·동결

- 정확히 T-01~T-24, 팩 순서, 중복 없음.
- before 인용은 해당 항목의 `앞 수첩`, after 인용은 `뒤 수첩`의 부분문자열이어야 한다.
- `independent: true`, `key_access: false`.
- JSON 하나만 출력하며 Markdown fence나 설명을 붙이지 않는다.
- 두 코더의 세 정형 필드가 하나라도 다르면 항목 전체가 익명 판정으로 간다.
- 합의·동결 전에는 키를 열지 않는다.
- AI 코더 일치는 모델 간 일치도이지 인간 신뢰도가 아니다.
