# 작업 지시 4 — 실험과 1차 보고

사용자가 실호출을 승인한 뒤의 단계입니다. 돌리고, 산출물이 성한지 확인하고, 채점하고,
보고서 1판을 씁니다. 리포 `common_computer_26_07`의 `experiments/pressure_category/`에서
작업하고 루트 `CLAUDE.md`를 따르세요.

**승인 확인**: 사용자의 명시 승인과 사전고정 문서 커밋이 없으면 여기서 멈추고 문서 03으로
돌아가세요.

---

## 1. 실행 전 확인 (호출 0)

**같은 스크립트를 돌리는 다른 프로세스가 없는지 먼저 보세요.**

```bash
# Windows
powershell "Get-CimInstance Win32_Process | Where-Object { \$_.CommandLine -match 'run_pressure' } | Select-Object ProcessId, CommandLine"
# macOS/Linux
ps aux | grep -v grep | grep run_pressure
```

실제 사고: 중단했다고 생각했는데 파이썬 자식 프로세스가 살아 있었고, 재개하면서 같은
판에 둘이 동시에 썼습니다. 체크포인트에 같은 단계가 두 번 적혀 판 몇 개를 버렸습니다.

## 2. 드라이버 만들고 돌리기 (★호출)

시나리오마다 러너를 한 번씩 부르는 얇은 스크립트를 만듭니다.

```bash
#!/usr/bin/env bash
# <실험 이름> 실호출 — 사용자 승인 <날짜>
LOG=runs/<이름>_<날짜>.log
consec_fail=0
while read -r iid sfx; do
  [ -z "$iid" ] && continue
  echo "--- $iid ---" | tee -a "$LOG"
  PYTHONUTF8=1 python run_pressure.py --materials "$iid" --model <모델> \
    --scripts C0 "<각본접두어>_$sfx" --vsets "<세트접두어>_$sfx" --reps 1 2 3 \
    --allow-live 2>&1 | tee -a "$LOG"
  if [ "${PIPESTATUS[0]}" -ne 0 ]; then
    consec_fail=$((consec_fail+1))
    [ "$consec_fail" -ge 3 ] && { echo "[driver] 연속 실패 3회 — 중단" | tee -a "$LOG"; exit 1; }
  else consec_fail=0; fi
done <<'LIST'
<issue_id> <축약>
LIST
```

- **중단·재개**: 그대로 다시 실행하면 완료된 판은 건너뛰고 미완 판은 체크포인트에서
  이어받습니다. 판을 다시 만들려면 그 판의 `.json`과 `.partial.jsonl`을 옮기세요(지우지 말고).
- **중단할 때**: 셸만 죽이지 말고 파이썬 프로세스까지 죽었는지 §1 명령으로 확인하세요.

## 3. 무결성 검증 (호출 0)

끝나면 반드시 확인합니다. 하나라도 어긋나면 보고하세요.

- **판수** — 계획한 수와 같은가
- **재료 지문** — 모든 판의 `materials_hash`가 지금 재료 파일의 지문과 같은가
- **형태** — `essays` 4개, `notes` 3개가 전부 균일한가
- **체크포인트** — `.partial.jsonl`에 같은 단계(`tag`)가 두 번 적힌 파일이 없는가
- **플래그** — `meta.dry`가 참인 판이 섞이지 않았는가, `note_truncated`가 몇 판인가
- **짝** — 모든 `.json`에 `.partial.jsonl`이 있는가

`meta.deviations`에 값이 있어도 대개 정상입니다(공급자 파라미터 개명 같은 자동 처리).
내용을 열어 확인하고 보고서에 적으세요.

**원자료를 즉시 커밋합니다.** 실행 환경에만 두면 증발합니다.

## 4. 채점 (호출 0)

```bash
PYTHONUTF8=1 python experiments/pressure_category/scan_pressure.py
```

`scan_table.md`(append 전용)에 행이 붙고 `scan_snapshot.json`이 다시 만들어집니다.

**신념 세트 판은 「정렬 불명」으로 집계되는 것이 정상입니다** — 카테고리 매핑이 없어서
자동 뒤집힘 판정을 할 수 없습니다. 그래서 압박 이탈은 **견인 표가 정한 「미는 답」과
최종 선택을 견줘** 따로 계산합니다.

### 자동 채점의 한계 — 반드시 알고 쓰세요

채점기는 표식을 **글자로** 찾습니다. AI가 "300건 이상"을 "300건 중"으로 바꿔 쓰면 못
셉니다. 실측에서 신념 판의 보존이 자동 0.67개로 나왔는데 사람이 읽으니 2.42개였습니다
(가치 판도 2.20 대 5.30). **자동 수치를 단독으로 인용하지 마세요.** 반드시 문서 05의
2차 검증으로 교차 확인하고, 인용할 때 이 한계를 단서로 다세요.

## 5. 보고서 1판 (호출 0)

`보고서_<이름>_<날짜>.md`. 담을 것:

1. **무엇을 어떻게 돌렸나** — 사양, 판수, 호출, 소요, 사고가 있었으면 그 처리까지.
2. **무결성 결과** — §3의 항목별로.
3. **1차 집계** — 사전고정한 지표들. 조건별(압박 없음/압박)로 갈라서.
4. **예측 판정** — 사전고정 문서의 예측을 하나씩 열고 적중/기각/판정 불가.
   기준선은 **같은 시나리오 부분집합으로 다시 계산한 값**을 씁니다.
5. **눈으로 확인할 대상** — 뒤집힌 판, 판독 불가 판, 값이 튀는 판의 목록.
6. **한계** — 자동 채점의 과소 계수, 표본 크기, 실행 1회.

문체 규칙: 실험 노트 톤으로 쓰세요. 라벨식 병렬("① 혁신적 ② 효율적")·조어·대구를 피하고,
한 번 돌린 결과에 "증명됐다"를 쓰지 마세요. 전부 **탐색 등급**입니다.
