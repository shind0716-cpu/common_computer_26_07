## 2. 설계 결정 1건 — 비교의 단위 (요한 선택 대기)

- **(i) 전 구간 비교 (권고·회의 문구 그대로)**: 저자 판은 저자 추출부터 끝까지 자기
  파이프라인으로. 각 판이 자기 팩트를 갖는다 — "시스템 대 시스템" 비교. 팩트가 다르므로
  FAR 절대값 비교가 아니라 **경향(라운드별 곡선·최종 수준) 비교**가 판정 대상.
- **(ii) 팩트 고정 비교**: 우리 추출물을 저자 형식 data 파일로 변환해 저자 판에 주입.
  토론·판정 단계만 격리 비교(통제 우수). 단 "논문 코드를 돌렸다"의 문면에서 반 발
  벗어난다. (i) 결과가 갈릴 때의 후속 진단 팔로 남겨두는 것을 권고.

콜 추정 (n=3): 저자 판 ~300콜(추출 9 + 배분 3 + 발화 96 + 판정 96×2축) ·
우리 판 ~288콜(발화 96 + 저자 축 96 + stance 96) · probe 96콜 → **총 ~700콜 ≈ $7**
(정밀 표는 G1 관문에서 확정).

## 3. 저자 판 실행 방식 (코드 무수정 원칙)

저자 코드는 CLI 인자(`--dataset scruples --model gpt --structure full`)와 **자기 리포
상대경로**(`data/`·`prompts/`)로 돈다. 로컬 스냅숏에 `data/` 가 없으므로:

1. `DelibTrace-main/data/` 에 **입력 데이터 파일만 생성**(scruples 형식, 대상 3건 —
   변환기는 우리 리포에 두고 산출만 그쪽에 놓는다. 코드·프롬프트는 손대지 않는다).
2. 작업 디렉터리를 저자 리포 루트로 해 단계 순서대로 실행:
   `facts.py → perspective.py → discussion.py → evaluation.py`.
3. 산출 전량을 즉시 우리 리포 `experiments/paper_repro/compare/authors_run/` 로 회수·
   커밋(7/21 원자료 소실 교훈). 저자 리포는 실행 후 입·산출물 잔재를 정리해 원상 복구.

주의: 저자 코드에는 체크포인트·상한이 없다 — **대상 3건짜리 데이터 파일 자체가 상한**
역할을 한다(전 데이터 파일을 놓으면 682건을 돈다). tqdm 진행으로 콜 폭주 감시.

## 6. 결정 반영 (2026-08-10 요한 — append)

**비교 단위 = (ii) 팩트 고정** 확정. 근거(요한): 추출 사양이 양쪽 동일(프롬프트 직독·
gpt-5·temp 0 — 프로브 실측 근거)하므로 추출 구현 차이까지 비교에 넣는 실익이 없다 —
실리 우선. 파생 이득: 분모(팩트·배분)가 같아져 FAR 을 경향이 아니라 **절대값·팩트
단위로 직접 비교**할 수 있다.

검토 문서 명시 의무: "논문 코드를 돌렸다"의 범위는 **토론·판정 구간**(discussion.py·
evaluation.py)이다 — 추출·배분은 저자 사양의 우리 산출물을 공통 주입(과대 표현 금지).
