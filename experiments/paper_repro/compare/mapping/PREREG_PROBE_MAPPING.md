## §0. 요약

1. 사실이 "얼마나 남았는가"를 남았다/사라졌다 2단이 아니라 **보존 등급 5단(L0~L4)** 으로 판정한다.
2. **등급 기준표(코드북)는 논문 데이터 0543에서 만들고, 점수는 민옥 본실험 재료에서 매긴다.**
3. 채점은 **겹침 구조** — 판정기가 전량, 사람이 조건 균형 50%. 주 지표는 판정기 기준으로 산출하고 사람 표본이 그 정답지가 된다.

## §1. 등급

| 등급 | 정의 | 판별 |
|---|---|---|
| **L0** | 원문 보존 | 핵심 명제 온전 + 고유 앵커(숫자·이름·날짜·조건)가 문면에 있음 |
| **L1** | 의역 | 핵심 명제 온전, 앵커 없음 |
| **L2** | 방향만 | 방향은 남고 수치·조건·시간이 소실 |
| **L3** | 간접 잔존 | 사실 진술 형태가 아니거나(규범·평가·질문문), 같은 텍스트의 다른 팩트에서 도출 가능 |
| **L4** | 부재 | 없음 |

**판별 순서**

```
앵커가 문면에 있나?
  YES → 핵심 명제 온전?  YES → L0
                         NO  → L2
  NO  → 핵심 명제가 사실 진술로 온전?  YES → L1
                                       NO  → 방향만 남음(사실 진술)?  YES → L2
                                                                      NO  → 그 명제를 간접 지시?  YES → L3
                                                                                                  NO  → L4
```

**L3 통합의 한계** — L3은 **문법 변형 잔존**(예: `should have checked in right away`)과 **다른 팩트에서 도출 가능한 것**이 섞인 칸이고, 이 설계로는 분리되지 않는다. 따라서 **L3은 상한 추정치**이지 실측이 아니다. 보고 시 이 문장을 반드시 붙인다.

완화: 서로 함의하는 팩트 쌍을 사전 마킹해 L3 집계에서 제외하고 제외 ID를 명시한다(LLM 호출 없음).

### 1.1 등급 밖 분류

| 코드 | 정의 | 처리 |
|---|---|---|
| `instruction_leak` | 프롬프트 지시문이 사실처럼 진술됨 | 판정 대상 제외. 건수 보고 |
| `confabulation` | 원문 팩트 목록에 없는 내용이 사실처럼 진술됨 | 별도 집계. **L4와 다르다** |
| `replay` | 1인칭 역할극이 대화 없이 재수행한 명제 | 전달 집계 제외 |
| `lang_drift` | 원 언어에서 이탈 | 플래그만. 제외하지 않음 |

| | |
|---|---|
| 주 지표 "생존" | **L0 · L1 · L2** |

## §3. 채점 구조 — 겹침

```
판정기 (gpt-5.4-mini)  →  36편 전량 채점        108콜
사람 (2인 독립)         →  그중 18편 전수 코딩   0콜
                           └─ 겹치는 216단위에서 정합 확인
```

| | 이유 |
|---|---|
| 주 지표는 판정기 기준으로 전량 산출 | 기준자가 하나여야 해리 폭(수첩 − 발화)이 오염되지 않음 |
| 사람 216단위는 같은 데이터 안의 정답지 | 신뢰도 근거가 외부가 아니라 내부에 있음 |
| 파이프라인은 기계로 돎 | 2단계 예산 스윕·3단계 가공 사다리로 확장 가능 |

> **금지** — 수첩은 사람, 발화는 판정기 식으로 **창별로 나누지 않는다.** 그렇게 하면 해리 폭이 실제 해리인지 채점자 차이인지 구별되지 않고 헤드라인이 무너진다.

### 3.1 대상 — 1차 범위

**② 수첩 조건 18런의 최종 시점.**

| | 편수 | 판정 단위 |
|---|---|---|
| 최종 수첩 | 18 | 216 |
| 최종 발화 | 18 | 216 |
| **합계** | **36** | **432** |

판정 단위 = 텍스트 × 팩트 12개. 라운드 전 구간·다른 기억 조건(①전체·③직전만) 확장은 1차 결과 후 결정.

### 3.2 사람 표본 — 어느 절반인가

**무작위 절반은 쓰지 않는다.**

| 기준 | 내용 |
|---|---|
| 조건 균형 | 진행 3종 × 2모델 = 6조건에서 반복 3개 중 1~2런씩 → 약 9런 |
| 창 균형 | 뽑은 런은 **수첩·발화를 쌍으로** 함께 코딩 |
| 강제 편입 | 판정기 3표가 갈린 것(`ambiguous`)은 **전량** |

→ 18편 · 216단위. 사람 작업 1.5~3시간/인.

### 3.3 코딩 규칙

1. **팩트 태그(우호/불리·중요도)를 가리고 코딩한다.** 안 그러면 "불리한 게 덜 남았다"가 모델 편향인지 코더 편향인지 구별되지 않는다.
2. **216단위를 셔플해서 배부한다.** 런 순서대로 하면 기준이 드리프트한다.
3. **불일치를 조정하지 않는다.** 갈린 채로 보고하고, 어느 등급 경계에 몰렸는지를 결과로 쓴다.

## §4. 전처리 (LLM 호출 0)

판정기에 태우기 전에 기계로 걷어낸다.

| 단계 | 처리 |
|---|---|
| 4a 지시문 사전 대조 | 프롬프트 원문 n-gram과 겹치면 `instruction_leak` → 제외, 건수 보고 |
| 4b 앵커 스캔 | 앵커 O + 기존 판정 O → **L0 확정, 묻지 않음** / 앵커 X + 기존 판정 X → **L4 확정, 묻지 않음** |
| 4c 함의 행렬 | 서로 함의하는 팩트 쌍 마킹 → L3 집계 제외 |
| 4d 구조 판별 | 배분·라운드·팩트 태그로 `replay` 분류. 판정기에 묻지 않음 |

앵커 O + 기존 판정 X 는 이상 케이스이므로 **사람이 직접 본다**(그 자체가 관찰거리).

## §5. 판정기 사양

| 항목 | 값 |
|---|---|
| 모델 | **gpt-5.4-mini** |
| 방식 | **배치** — 텍스트 1편에 대해 후보 팩트 전부를 한 콜로 |
| 출력 | 등급 토큰 + `ambiguous` 불리언. **자유 서술 금지** |
| 반복 | **n = 3, 다수결.** 3표가 갈리면 `ambiguous: true` + 사람 표본 강제 편입 |
| 기록 | 원표 3개 · 모델 스냅샷 · 프롬프트 버전 해시 · usage 전량 |
| 온도 | 명시 전송. **API가 거부하면 로그 남기고 중단 후 보고** |

**원표를 반드시 남긴다.** 다수결 결과만 저장하면 판정기 흔들림을 사후에 못 잰다 — 비교 파일럿 n=1의 재발이다.

## §6. 에스컬레이션 — 문제 생기면 사람을 더 쓴다

즉흥 대응이 아니라 사전 규칙이다. 조건에 걸리면 자동으로 다음 단으로 올린다.

| 단 | 발동 조건 | 대응 |
|---|---|---|
| **E0** | 2인 코딩 κ < 0.60 | 판별 규칙 보강 후 **재코딩.** 판정기 단계로 넘어가지 않음 |
| **E1** | 판정기–사람 **±1단 이내 일치율 < 80%** | 사람 표본을 **나머지 절반까지 확대**(전수 432단위) |
| **E2** | 특정 등급에서만 일치율 붕괴 | **그 등급 구간만** 사람 확대. 전수 전환 안 함 |
| **E3** | `ambiguous` 비율 > 20% | 코드북 보강 후 해당 건 재판정. 콜 늘리지 않고 사람으로 흡수 |
| **E4** | 실측 단가가 가정의 3배 초과 | **첫 10콜에서 확인하고 중단.** 나머지를 사람 전수로 전환 |

**E1·E2가 발동해도 콜은 늘지 않는다** — 이미 나온 출력에 사람 라벨을 더 붙이는 구조라, 예산이 아니라 시간만 든다.

## §13. 이 설계가 답하지 못하는 것

- **"물으니 답했다"와 "기억한다"를 구분하지 못한다.** 수첩은 자발 기록이라 회고보다 낫지만 여전히 "쓰라고 시킨 것"이다.
- **"수첩에 있다"가 "판단에 쓴다"를 뜻하지 않는다.** 그 팩트가 필요한 새 문제를 풀려봐야 안다.
- **등급이 진짜 순서열인지는 설계자 정의다.** 각 등급을 처음 보는 모델에 주고 원문 복원을 시키는 재구성 프로브로 재면 축이 연구자 정의가 아니게 된다. 그 전에는 정보이론 용어를 쓰지 않는다.
- **재료가 바뀌면 L3 경계는 재보정이 필요하다.** 0543은 도덕 판단 과제라 규범문이 많고, 민옥 재료는 사실 판단이라 적게 나올 것이다.
- **작화는 관문 2개 모델 밖의 제3 경로다.** 앵커 스캔은 정확한 회상과 작화 속 앵커를 구별하지 못한다.

### C-1. 앵커 필드 부재 — §4b·§1(L0 정의) 전제 붕괴

`data/facts/facts_issue_camp.json` 에 **`anchors` 필드가 없다.** PREREG_v1 §3의
"각 팩트 고유 앵커"는 재료 설계 규칙이었을 뿐 데이터 필드로 저장되지 않았다.
L0의 정의가 "앵커가 문면에 있음"이므로 앵커 사전 제작이 **선행 작업**이 된다.
→ Step 1을 코드북 재판독에서 **앵커 사전 제작**으로 교체(`TASK_STEP1.md` 신판).
→ 사전은 별도 파일 `anchors_camp.json`. 팩트 파일 직접 수정 금지(원자료 규약).

### C-2. 등급 L3 삭제 — §1·§2 전제 붕괴

구 L3(간접 잔존 중 문법 변형)이 **민옥 재료에 존재하지 않는다.** 규범 표현 실측:

| 창 | n | 규범표현 포함 |
|---|---|---|
| essay | 216 | 26 (12%) — 논증 수사이지 팩트 변형 아님 |
| **note** | **54** | **0 (0%)** |
| recall | 54 | 8 (15%) — 총회 조건 진술이지 팩트 변형 아님 |

구 L3은 0543(AITA 도덕 판단 과제)의 산물이었다.
→ **등급 4단 확정: L0 원문 / L1 의역 / L2 방향만 / L4 부재.**
→ §2 컷오프는 유지(L0~L2 = 생존). L3 병행 보고 행은 삭제.

### C-3. recall 소재 오인 — §3·§4 범위 변경

recall은 논문 재현 트랙 전용이 아니라 **민옥 본실험 54런 전부에 존재**하며,
`judgments/*/records` 키가 `essay_r0~r3` + `carrier`뿐이므로 **한 번도 채점된 적이 없다.**
이것이 사전등록 미이행 항목(작화·회상 지표)의 정체다.
→ 1차 범위를 **② 수첩 조건 18런 × 3창**(최종 수첩·최종 발화·recall)으로 확정.

### C-4. 채점 구조 교체 — §3·§5·§7 대체

정찰에서 **앵커 스캔 × 기존 판정 교차만으로 판정 단위의 상당수가 확정**되고,
