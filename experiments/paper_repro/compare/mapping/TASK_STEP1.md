## 절차

### 1. 20셀 준비

`MUTUAL_REVIEW.md`의 8/12 append에서 20셀의 **좌표(이슈·stage·방향·fact_id)와 직접 인용**을 뽑는다.
`data/debates/`에서 해당 발화 원문 전문을 붙인다 — 인용만으로 등급을 매기지 말 것.

### 2. 블라인드 처리

재판독용 자료를 만들 때 아래를 **가린다.**

- 원판독 범주(판정 경계 / 발화 부재)
- 어느 판(저자/우리)이 "언급됨"으로 판정했는지
- 팩트 태그(critical 여부 등)

셀 순서를 셔플하고, `recode_20cells.jsonl`에 셔플 시드를 기록한다.

### 3. 2인 독립 코딩

각 셀에 등급 하나 + `ambiguous` 불리언.
**서로 상의하지 않는다. 끝난 뒤에도 합의로 조정하지 않는다.**

> 2인 확보가 안 되면 여기서 멈추고 보고할 것. 1인 코딩으로 진행하지 않는다 — κ가 안 나오면 게이트 E0을 판정할 수 없다.

### 4. 대응표

새 등급 vs 원판독 범주를 교차표로 낸다.

| | L0 | L1 | L2 | L3 | L4 |
|---|---|---|---|---|---|
| 판정 경계 (15셀) | | | | | |
| 발화 부재 (5셀) | | | | | |

**예상**: 판정 경계 → L1~L3, 발화 부재 → L3~L4.
**예상과 다르면 등급 정의를 고치지 말고 그 사실을 기록한다.** 정의 수정은 사람 판단 사항이다.

### 5. 앵커 사례 추출

등급마다 원문 인용 **2건씩**. 이게 코드북의 실체다.
관측되지 않은 등급은 사례를 지어내지 말고 "미관측"으로 남긴다.

### 6. 게이트 판정

`codebook_validation.md`에 아래를 기록한다.

| 게이트 | 기준 | 미달 시 |
|---|---|---|
| **E0** | 2인 코딩 κ ≥ 0.60 | 판별 규칙 보강 후 재코딩. **Step 2로 넘어가지 않음** |
| G2 | `ambiguous` 비율 ≤ 20% | 애매 사례를 코드북 결정 규칙에 반영 |
| G3 | 실제 관측된 등급 4단 이상 | 3단 이하면 사다리 과설계 — **축소 제안하고 사람 판단 대기** |

불일치 셀은 **어느 등급 경계에 몰렸는지**를 함께 적는다. L1/L2 경계에 몰렸다면 그건 코드북을 고칠 신호다.
