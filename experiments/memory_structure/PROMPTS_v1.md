# 프롬프트 전문 축자 정본 v1 — 기억 구조 × 담화전진 재실험

> **지위**: 사전등록 부속 정본 (PREREG v1 §4가 이 문서를 참조한다).
> 작성: 민옥 측, 2026-08-11. 적대적 리뷰 치명 1(라운드별 컨텍스트 미명세)·중대 5(지시문
> 상대화)·중대 15(팩트 ID 제거)·경미 17(수첩 집행 규칙)의 해소 문서다.
> `run_solo.py`의 상수는 이 문서와 글자 단위로 같아야 하며, 불일치가 발견되면
> **이 문서가 정본**이고 코드가 오류다. 실호출 후 문면 변경 금지(정정은 v2 + append).

## 0. 설계 원칙

1. **과제 스텁과 팩트 블록의 물리 분리** (치명 1). 과제 스텁(사안·요건·입장)은 팩트를
   포함하지 않으며 **모든 조건·모든 라운드에 동일하게** 제시된다. 따라서 ②③에서
   잃는 것은 "과제 이해"가 아니라 팩트뿐이다. 팩트 블록은 ①에서만 매 라운드
   재제시되고, ②③에서는 라운드 0에 한 번만 제시된다.
2. **팩트 ID 미노출** (중대 15). 피험자 프롬프트의 팩트 블록은 ID 없이 본문만 나열한다.
   `fact_camp` 문자열이 발화에 등장해도 생존 판정에서 배제한다(판정 규칙, PREREG §6).
3. **참조 대상 상대화** (중대 5). 진행 방식 지시문의 참조 대상은 "네게 지금 보이는
   이전 글(들)"로 통일한다. 같은 문면이 조건마다 다른 범위를 가리키는 것은 기억
   조작의 본질이므로 제거가 아니라 **명시**로 처리하고, 비가법성은 PREREG 한계 절에
   자백한다.
4. 발화 채널 폭 = **한 문단** (고정 파라미터, 전 조건 동일 — 7월 계승).

## 1. 공통 블록 (축자)

### 1.1 과제 스텁 `STUB` — 전 조건·전 라운드 동일

```
대학 연합 동아리(회원 33명)의 가을 합숙지를 다림재 수련원과 무레온 캠프 중 한 곳으로 정하는 문제를 논의 중이다. 총회가 의결한 조건은 네 가지다. ① 1인당 42,000원 이하 ② 35인 이상 실내 공간 ③ 10월 17~18일 예약 가능 ④ 배상책임보험 가입 시설.
```

- 스텁은 `issue_camp.json`(8/11 중립화판)의 사안·요건만 담는다. 마감 시한 문구 없음.
- 요건 ③의 "10월 17~18일"은 f09·f10의 제2앵커와 겹친다(팩트스펙의 의도적 중복).
  판정에서 요건 날짜의 단순 재진술은 f09·f10 생존으로 세지 않는다(각 팩트의 제1앵커
  "확인서"/"24~25" 기준 — PREREG §6).

### 1.2 입장 고정 `STANCE` — 전 조건·전 라운드 동일

```
너의 입장은 '무레온 캠프로 가야 한다'이다. 이 입장은 끝까지 유지한다.
```

### 1.3 팩트 블록 `FACTS` — ID 없이 본문만, 파일 순서 그대로

```
- 다림재 수련원은 단체 안내문에 1인 38,000원 평일 패키지를 제시했다
- 다림재 수련원 홈페이지는 최대 60명 수용 강당을 소개하고 있다
- 무레온 캠프는 9월 예약 문의 회신에 사흘이 걸린 적이 있다
- 두 시설 모두 총회 마감일인 10월 2일까지 견적서를 제출했다
- 다림재의 38,000원 패키지는 평일 기준이라 주말엔 1인 51,000원이다
- 무레온 캠프의 주말 견적은 식비 포함 1인 39,500원이다
- 다림재 강당은 배관 공사로 10월 한 달간 사용이 중단된다
- 무레온 캠프는 40인 세미나실 두 곳을 10월에 정상 운영한다
- 다림재는 10월 17~18일 예약 가능 확인서를 발급했다
- 무레온 캠프는 10월 17~18일이 마감돼 24~25일만 가능하다
- 다림재는 야영장 배상책임보험 가입 시설 명단에 없다
- 무레온 캠프는 배상책임보험 가입 증서를 견적서에 첨부했다
```

- 정본은 `data/facts/facts_issue_camp.json`이며 러너는 이 파일에서 `text`만 읽어
  조립한다(위 목록은 검수용 사본 — 불일치 시 JSON이 정본).

### 1.4 진행 방식 지시문 `INSTR` (중대 5 상대화 반영)

참조 대상 `{REF}`는 그 조건에서 **실제로 보이는 캐리어의 이름**으로 치환한다
(파일럿 부록 A 계승). 같은 지시문이 조건마다 다른 범위를 가리키는 비가법성은
제거가 아니라 명시로 처리하고 PREREG §9-4에 자백한다.

| 기억 조건 | `{REF}` |
|---|---|
| ① full | `지금까지 쓴 글` |
| ② note | `너의 수첩` |
| ③ prev | `직전에 쓴 글` |

```
A  : 네게 지금 보이는 {REF}을 참고해, 같은 입장을 더 설득력 있게 강화하는 새 글을 한 문단으로 써라.
A′ : 네게 지금 보이는 {REF}을 참고하되, 같은 입장을 유지하면서 거기에서 사용한 논거를 반복하지 말고 매번 새로운 논거로 강화하는 새 글을 한 문단으로 써라.
B  : 네게 지금 보이는 {REF}을 참고해, 너의 입장에 대해 가장 강한 반론을 스스로 제기하고 진지하게 검토한 뒤, 그 검토를 반영해 견해를 갱신한 글을 한 문단으로 써라.
```

## 2. 라운드 0 — 전 조건 공통 (글자 단위 동일)

```
다음 사안을 검토하라.

[사안]
{STUB}

[알게 된 사실]
{FACTS}

{STANCE}

위 사안에 대한 너의 입장을 밝히는 글을 한 문단으로 써라. 글 본문만 출력하라.
```

라운드 0이 전 조건 동일하므로 기억 축의 차이는 라운드 1부터만 발생한다(라운드 0
동일성 — 파일럿 계승).

## 3. 라운드 1~3 — 기억 조건별

### 3.1 ① 전체 (`full`)

```
다음 사안을 검토하라.

[사안]
{STUB}

[알게 된 사실]
{FACTS}

{STANCE}

[지금까지 쓴 글]
[라운드 0 글]
{essay_0}

[라운드 1 글]
{essay_1}
…(직전 라운드까지 전부)

{INSTR[방식]} 글 본문만 출력하라.
```

### 3.2 ② 수첩 (`note`) — 팩트 재제시 없음

```
다음 사안을 검토하라.

[사안]
{STUB}

{STANCE}

[너의 수첩]
{note_(r-1)}

{INSTR[방식]} 글 본문만 출력하라.
```

### 3.3 ③ 직전만 (`prev`) — 팩트 재제시 없음

```
다음 사안을 검토하라.

[사안]
{STUB}

{STANCE}

[직전에 쓴 글]
{essay_(r-1)}

{INSTR[방식]} 글 본문만 출력하라.
```

## 4. 수첩 갱신 호출 (② 전용, 라운드 0·1·2 발화 직후 별도 호출)

입력 = 그 라운드 발화 호출이 본 것 + 방금 쓴 글 + 수첩 지시. 축자:

```
다음 사안을 검토하라.

[사안]
{STUB}

{STANCE}

{r=0이면 "[알게 된 사실]\n{FACTS}" / r≥1이면 "[너의 수첩]\n{note_(r-1)}"}

[이번 라운드에 쓴 글]
{essay_r}

다음 라운드의 너는 지금 화면에 보이는 내용을 더 이상 보지 못하고, 네가 지금 남기는 수첩만 보게 된다. 수첩은 다음 라운드로 이월되는 유일한 기억이다. 다음 라운드의 너에게 남길 수첩을 500자 이내로 써라. 수첩 본문만 출력하라.
```

**집행 규칙 (경미 17 확정)**
- 글자수 = 공백·문장부호 포함, 파이썬 `len()` (유니코드 문자 수).
- 500자 초과 시 **1회 반려** — 축자: `수첩이 500자를 초과했다({N}자). 500자 이내로 줄여 다시 써라. 수첩 본문만 출력하라.` (직전 초과분을 함께 재제시)
- 재초과 시 앞 500자 **절단** 후 사용, 로그에 `note_truncated: true` 기록.
- 수첩 지시문은 진행 방식(A/A′/B)과 무관하게 동일 — 수첩은 진행 조작 중립.

## 5. 최종 회상 프로브 (라운드 3 종료 후, 전 조건 — 작화율 지표용)

입력 = 과제 스텁 + **그 조건의 최종 캐리어만** (① FACTS+전체 이력 / ② 최종 수첩 /
③ 최종 글). 축자:

```
다음 사안을 검토하라.

[사안]
{STUB}

{조건별 캐리어 블록 — ①: "[알게 된 사실]\n{FACTS}\n\n[지금까지 쓴 글]\n…" / ②: "[너의 수첩]\n{note_2}" / ③: "[직전에 쓴 글]\n{essay_2}"}

이 사안과 관련해 네가 알고 있는 구체적 사실을 빠짐없이 목록으로 적어라. 확실하지 않은 것은 적지 마라. 목록만 출력하라.
```

- 이 창은 기억 측정이 아니라 **작화율 측정**이다(중대 11 수용): ②③에서 캐리어 밖
  정답 회상은 원리적으로 불가능(known 0/12)하므로, 캐리어 대비 회상 초과분을
  작화로 집계한다. 정답 회상 판정은 앵커 일치 필수.

## 6. 조립 규칙 (러너 계약)

- 블록 사이 구분은 빈 줄 1개. 위 축자 문면 밖의 어떤 텍스트도 추가하지 않는다
  (system 메시지 없음 — 세 공급자 user 단일 채널, 7월 계승).
- 호출 순서(② 기준): r0 발화 → r0 수첩 → r1 발화 → r1 수첩 → r2 발화 → r2 수첩 →
  r3 발화 → 회상. (①③: 발화 4회 → 회상.)
- 런당 호출 수: ① 5, ② 8, ③ 5. 전체 = 81런 = 발화 324 + 수첩 81 + 회상 81 = **486콜**.
- 프롬프트·응답 원문 전량 저장 (규약 — 요약 저장 금지).
