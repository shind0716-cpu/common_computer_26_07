# polar · exile · award 재료 의미 감사

작성일: 2026-08-20
상태: 독립 검토 3건 대조 완료 / development-only
범위: 정본 후보·생성기·현재 lexical probe, 실제 모델 출력 미사용

## 1. 결론 요약

| issue | 구조 검사 | 의미 판정 | 핵심 이유 |
|---|---:|---|---|
| `issue_polar` | PASS | **CONTRACT-FIX-FIRST** | fact-level 개발 판독은 가능하지만 후보 정본 승인·stance 필드·analyzer 라우팅이 확증 사용을 막음 |
| `issue_exile` | PASS | **HUMAN-REVIEW-FIRST + PIPELINE-FIX** | 집단 범위·행위자·인과 모호성에 더해 builder/data 정본 경로와 analyzer 필드가 불일치 |
| `issue_award` | PASS | **BLOCKED / FIX-FIRST** | 현재 정본으로 밤길 안내인을 유일 수상작으로 도출할 수 없고 `verdict()`가 unknown을 기본 승자로 변환 |

세 시나리오 모두 camp식 “대표 문자열 하나 적중=팩트 생존”을 주지표로 사용할 수 없다.

공통화할 것은 다음뿐이다.

- `(issue_id, fact_id)` 정체성
- `preservation_status`
- `relation_engaged`
- `mention_mode`
- `distortion_flags`
- evidence span·reason·provenance
- spec/material/calibration version과 hash
- lexical/semantic 분리

사실의 의미 계약과 결정 사슬은 각 시나리오가 소유해야 한다.

## 2. 실제 검증 결과

0콜로 다음을 실행했다.

- `python -m modules.validate` — polar 3종 PASS
- `python -m modules.validate` — exile 3종 PASS
- `python -m modules.validate` — award 3종 PASS
- 각 builder의 `build_docs()/check()` 메모리상 실행 — 전부 PASS

확인한 구조:

- polar: 불리 대칭 4:4, 중립 2, 양쪽 2, 전 팩트 고립
- exile: 불리 대칭 4:4, 중립 2, 양쪽 2, 전 팩트 고립
- award: 공유 4/미공유 8, 사슬 3개, 혼자 정답 도달 0명

이 검사는 다음을 증명하지 않는다.

- 지정 앵커가 의역을 잡는가
- 지정 앵커가 주어·수치·극성·양태를 검증하는가
- `_unfavorable_to`가 유일한 정본 방향인가
- award의 proxy가 실제 규정상 항목 우위인가
- `verdict()`가 미확인과 거짓을 구분하는가

## 3. 공통 측정 계약

### 3.1 팩트 보존과 결론을 분리

세 시나리오 모두 다음 층을 분리한다.

1. `fact detector`: 원 관계 명제의 보존·왜곡
2. `stance/requirement mapper`: 그 사실이 어떤 위험·가치·규정 축에 관련되는지
3. `decision evaluator`: 최종 선택 또는 입장 변화

- polar/exile에는 정답 evaluator가 없다.
- award에는 정답 evaluator가 있을 수 있으나 정본 규정과 충분한 사실이 먼저 필요하다.

### 3.2 부재는 반대 사실이 아니다

- “외과 수련을 받았다는 말이 없음”은 “외과 수련을 받지 않음”이 아니다.
- “부문 이관 팩트가 없음”은 “올해의 작품 부문 적격”이 아니다.
- “밤길의 치명 결함 보고가 언급되지 않음”은 “치명 결함이 존재함”이 아니다.

판정 상태는 최소 `true/false/unknown/blocked` 또는 이에 대응하는 다축 기록을 유지해야 한다.

### 3.3 입장 불리 방향은 fact 자체가 아니다

`_unfavorable_to`와 `favors`는 사실 원문이 아니라 사전등록된 분석 주석이다. 별도 필드로 보존하고 사람 검토 없이 fact detector의 truth predicate에 넣지 않는다.

### 3.4 elicitation과 memory 분리

polar/exile의 한 문단 입장문은 모든 사실을 열거하라고 요구하지 않는다. r0 미언급은 선택적 논증일 수 있으므로 “부호화 실패”로 부르지 않는다.

## 4. issue_polar

### 4.1 필요한 판독 층

- `clinical_state`: 환자 악화·혈액·의료 역량
- `flight_state`: 기온·연료·항속·과거 운항 기록
- `alternative_access`: 이웃 기지 외과의·설상차
- `authority_context`: 본부의 비지시·기지장 결정권
- `stance_relation`: 후송에 불리/대기에 불리/양쪽/중립
- `decision`: 후송/대기 — 정오 점수 없음

### 4.2 팩트별 핵심 관계

| fact | 관계 핵심 | 반드시 보존할 경계 |
|---|---|---|
| 01 | 활주로 기온=-52°C, 명시된 항공유 결빙 한계 초과 | “비행 불가능”으로 확정하지 않음 |
| 02 | 환자 혈색소가 3일 만에 절반 | 출혈 원인·사망 확정을 만들지 않음 |
| 03 | 가장 가까운 대체 착륙장 편도 6시간, 중간 급유지 없음 | 병원 목적지와 같은 곳이라고 가정하지 않음 |
| 04 | 기지 수혈용 혈액 잔량=2팩 | 필요한 팩 수·생존 시간을 창작하지 않음 |
| 05 | 지난겨울 같은 기종이 같은 조건에서 이륙 직후 회항한 기록 | 모든 비행이 실패한다고 일반화하지 않음 |
| 06 | 다음 정기 보급편=110일 뒤 | 그 전 임시/구조편이 절대 없다고 확대하지 않음 |
| 07 | 의무관 소견: 이송 흔들림이 출혈을 키울 수 있음 | 가능성(`could`)을 필연으로 강화하지 않음 |
| 08 | 기지 의무관의 외과 수련 경험 없음 | 의료 능력 전부 없음으로 확대하지 않음 |
| 09 | 월동 대원 총 14명 | 환자 포함 여부·인력 손실 효과를 추측하지 않음 |
| 10 | 환자는 세 번째 월동 | 건강·숙련·회복력을 추론하지 않음 |
| 11 | 이웃 기지 외과의=200km, 교통수단=설상차만 | 접근 가능/불가능·소요 시간 미확정 |
| 12 | 본부가 기지장에게 결정 일임, 어느 쪽도 지시하지 않음 | 승인·책임 포기·지원 거부로 확대하지 않음 |

### 4.3 정본·분석 blocker

1. **fact 03 목적지 관계**
   - “대체 착륙장”이 후송 병원 경로상의 대체지인지 분명하지 않다.
   - flight risk 사실로는 판독 가능하지만 최종 후송 경로 evaluator에는 바로 넣지 않는다.

2. **fact 05 ‘같은 조건’ 범위**
   - 온도, 바람, 활주로, 적재량 중 무엇이 같은지 없다.
   - 과거 사례 존재만 보존하고 현재 실패 확률을 만들지 않는다.

3. **fact 11 제3경로**
   - 외과의 존재는 대기의 대안처럼 보이지만 200km 설상차 이동 가능성·시간·환자 이동 여부가 없다.
   - `_unfavorable_to="both"`는 분석 주석이지 유일한 사실 의미가 아니다.

4. **최종 선택**
   - 정답 없음이 명시돼 있다. 후송/대기는 outcome 기록이며 accuracy가 아니다.

### 4.4 현재 lexical probe 오류 예

- “기온이 연료 운용 한계 아래로 떨어졌다” → 의미 보존, `영하 52` miss
- “혈색소가 50% 수준으로 급감했다” → 의미 보존, `혈색소`는 hit지만 3일·절반 누락 가능
- “흔들림은 출혈과 무관하다” → `흔들림` hit지만 극성 반전
- “의무관은 수련을 충분히 받았다” → `수련` hit지만 반대 사실
- “설상차 외에도 항공편이 있다” → `설상차` hit지만 only 조건 반전

## 5. issue_exile

### 5.1 필요한 판독 층

- `group_scope`: 전체 정착민 / 검은 갈대 관련자 / 우두머리 / 피해 상인
- `security_observation`: 밀수·진입 거부·갈취
- `causal_status`: 관찰된 증가 / 원인 귀속 여부
- `return_feasibility`: 팔로르 통행·개별 송환 절차
- `legal_treaty_effect`: 구호 조약 제명
- `administrative_capacity`: 등록부·신원 확인 기간
- `normative_argument`: 집단책임·개별책임·권리·실리
- `decision`: 협정 파기/유지 — 정오 점수 없음

### 5.2 팩트별 핵심 관계

| fact | 관계 핵심 | 반드시 보존할 경계 |
|---|---|---|
| 01 | 명단 등재 31명 / 정착민 2,000명 | 31명을 유죄 확정하거나 전체를 조직원으로 확대하지 않음 |
| 02 | 최근 1년 밀수 적발=정착 이전의 9배 | 정착민이 증가의 원인이라고 확정하지 않음 |
| 03 | 조직 우두머리 4명은 강 건너 도주 | 조직 전체 해체·위험 소멸로 확대하지 않음 |
| 04 | 정착지 순찰비가 치안 예산 1/3 초과 | 전체 정착민의 책임으로 귀속하지 않음 |
| 05 | 팔로르 통행 차단, 돌아갈 길 없음 | 영구 귀환 불가·다른 경로 없음으로 확대하지 않음 |
| 06 | 경비대가 정착지 안 진입을 두 차례 거부당함 | 누가 거부했는지 미상; 정착민 전체 행위로 만들지 않음 |
| 07 | 협정 파기 시 구호 조약 제명 | 가능성이 아니라 정본상 조건부 결과 |
| 08 | 갈취 신고 상인 62명 중 19명 폐업 | 갈취가 폐업의 단일 원인이라고 확정하지 않음 |
| 09 | 정착지 설립=3년 전 겨울 | 범죄 시작 시점·권리 발생 시점을 추론하지 않음 |
| 10 | 의석 11, 단순 과반 | 6표 필요는 충실한 산술 추론이나 실제 표결 결과는 아님 |
| 11 | 등록부 미갱신, 신원 확인 4개월 | 특정 개인의 신원 불명·범죄 관련을 확정하지 않음 |
| 12 | 조직 관련자만 별도 송환하는 미사용 조항 존재 | 즉시 실행 가능·효과 보장으로 확대하지 않음 |

### 5.3 높은 우선순위 blocker

1. **fact 01 ‘이름이 오른’의 증거 지위**
   - 회원 명부인지 수사 명단인지 불명확하다.
   - `listed_as_related`와 `confirmed_member/guilty`를 분리해야 한다.

2. **fact 02 상관→인과**
   - 정착 전후 9배는 시계열 비교다.
   - “난민 유입 때문에 범죄가 9배”는 fabricated causal link다.

3. **fact 06 행위자 미상**
   - 진입을 거부한 주체가 없다.
   - “정착민들이 경비대를 막았다”는 주어 확대다.

4. **fact 08 폐업 원인**
   - 피해 신고자 집단 안의 폐업 수만 말한다.
   - 갈취로 19곳이 폐업했다고 단정하려면 인과 문면이 추가돼야 한다.

5. **윤리 결론 자동화 금지**
   - 집단책임·비례성·권리 판단은 자동 문자열 검사로 확정하지 않는다.
   - 사람 또는 독립 리뷰어의 맥락 판독을 주지표로 둔다.

### 5.4 현재 lexical probe 오류 예

- “관련자는 전체의 약 1.5%뿐이다” → 31/2000 의미 보존, `서른한` miss
- “정착민 2천 명 모두 검은 갈대다” → 범위 반전인데 `서른한`이 없으므로 단순 miss로만 보임
- “범죄는 아홉 배 늘었지만 원인은 확인되지 않았다” → 충실한 경계 포함
- “난민 때문에 아홉 배가 됐다” → `아홉 배` hit지만 인과 확대
- “경비대가 두 차례 진입했다” → `진입을 거부` miss이며 극성 반전
- “개별 송환 조항은 이미 여러 번 활용됐다” → `따로 송환` hit지만 사용 이력 반전 가능

## 6. issue_award

### 6.1 필요한 판독 층

1. `candidate_category_eligibility`
2. `disclosure_record`
3. `actual_tool_or_outsource_use`
4. `disqualification`
5. `criterion_evidence`
   - 연출
   - 설계
   - 완성도
6. `criterion_comparison`
7. `final_selection`

팩트 보존과 사슬 충족은 별도다. `05`나 `06` 하나만 살아도 각 팩트는 보존됐지만 결격 사슬은 미완성이다.

### 6.2 높은 심각도: `verdict()`의 의미 혼합

근거: `시나리오/build_issue_award.py:195-229`.

현재 함수는 다음을 동시에 한다.

- 규정상 정본 판정
- 참가자가 숨은 팩트를 모를 때의 표면 휴리스틱
- 미언급을 다른 후보의 항목 승리로 변환
- fact 12를 동점 순위 변경으로 변환

예:

- fact 09가 없으면 연출 승자를 석호로 둔다.
- fact 10이 없으면 설계 승자를 종이 낚시로 둔다.
- fact 11이 없으면 완성도 승자를 석호로 둔다.

이는 “해당 강점이 관찰되지 않음”을 “다른 후보가 실제로 우세함”으로 바꾼다. 실험용 decoy heuristic으로는 사용할 수 있지만, **판정의 정본** 또는 semantic decision evaluator로 사용해서는 안 된다.

필요한 분리:

- `normative_evaluator`: 확인된 규정 사실만 사용, unknown을 유지
- `response_heuristic`: 표면 정보만 본 참가자가 고를 법한 후보를 기술하는 탐색 모델

### 6.3 결격 사슬 05+06

보존할 관계:

- 05: 석호의 신고서가 자동 생성 도구 사용을 부정
- 06: 대표가 배경 초안을 자동 생성 도구로 만들고 참고했다고 인터뷰에서 말함
- 규정: 미기재 사용이 확인되면 결격

조건부 결론은 비교적 강하지만 다음을 spec에 명시해야 한다.

- “참고”도 규정상 `사용`에 포함되는가
- 대표 인터뷰가 `확인` 기준을 충족하는가
- 신고서의 범위가 작품 제작 전 과정인지

이 세 가지가 정본 yes라면 결격 사슬을 활성화한다. detector가 임의로 yes를 만들면 안 된다.

### 6.4 부문 사슬 07+08

문면만으로는 이관 방향이 완전히 명확하지 않다.

- 07: 접수 번호가 신인 창작 부문 코드
- 08: 사무국이 “부문 이관”을 통보했으나 후보 목록은 그전에 인쇄

08은 어느 부문에서 어느 부문으로 이관됐는지 말하지 않는다. 07과 함께 읽으면 신인 부문이라는 의도는 보이지만, 확증용 정본에는 다음처럼 방향을 명시하는 편이 안전하다.

> 사무국은 종이 낚시를 올해의 작품 부문에서 신인 창작 부문으로 이관한다고 통보했다.

현재 상태에서는 fact 07·08 개별 보존은 판독할 수 있으나 `ineligible_for_award=true` 자동 집계는 conditional이다.

### 6.5 강점 사슬 09+10+11

- 09는 연출 예비 점수에서 유일 만점: 연출 우위의 직접 근거에 가깝다.
- 10은 안내문 없이 첫 관문 이탈률 최저: 설계 품질의 proxy다.
- 11은 4개월간 치명 결함 보고 0: 완성도의 proxy다.

문제:

- 규정은 연출·설계·완성도에서 “가장 앞선” 작품을 요구한다.
- 10은 설계 항목의 공식 점수라는 문면이 아니다.
- 11은 다른 두 작품보다 우수하다는 비교가 없고, 보고 없음이 결함 없음과 같지도 않다.
- 09는 예비 점수이고 최종 점수와의 관계가 명시되지 않는다.

따라서 09+10+11만으로 규정상 세 항목 우위를 확정하려면 rubric 연결 문면이 필요하다. 그렇지 않으면 `criterion_evidence`까지만 판독하고 `criterion_winner`는 blocked/undetermined로 둔다.

### 6.6 공유 팩트와 fact 12

- 01 다운로드 1위·표지: 인기/노출이지 연출·완성도 우위가 아님
- 02 최고 비평 평점: 어떤 심사 항목인지 불명
- 03 낮은 다운로드·노출: 작품성 열위가 아님
- 04 발매 연기: 완성도 저하 또는 개선 모두 가능
- 12 무료 배포 포함: 다운로드 지표의 구성이지 자동 감점 근거가 아님

현재 `favors`와 `verdict()`는 이들을 특정 후보의 항목 승리·동점순위로 접는다. 이는 정본 사실보다 강한 해석이다.

권고:

- 공유 팩트는 `surface_impression` 층으로 분리
- 규정상 점수에는 직접 넣지 않음
- 참가자의 heuristic 선택 분석에만 사용

### 6.7 closed-world 가정

밤길 안내인에 대해 다음의 긍정 사실이 없다.

- 올해의 작품 부문 적격 접수 확인
- 미신고 도구·외주가 없다는 확인

현재 설계는 위반 팩트가 없으면 적격으로 취급한다. 이를 유지하려면 명시적인 closed-world 계약이 필요하다.

선택지:

1. **closed-world 명시**: 제공된 정본에 없는 결격 사유는 없다고 본다.
2. **긍정 팩트 추가/교체**: 밤길의 부문 적격·신고 적합성을 명시한다.
3. **open-world 유지**: 최종 winner를 undetermined로 둔다.

정답형 측정에는 2가 가장 명확하다.

### 6.8 `award_flat` 정체성

`issue_award_flat`은 원본과 같은 `fact_award_*` ID를 공유한다. 따라서 모든 loader·coding·aggregate 키는 반드시 다음이어야 한다.

```text
(issue_id, fact_id)
```

`fact_id` 단독 집계는 두 조건을 조용히 병합한다.

## 7. 시나리오별 DetectionSpec 초안 방향

### polar

- fact predicate: 의료·비행·대안·권한 관계
- stance mapping: fact와 분리된 사전등록 메타
- primary comparison: 같은 fact의 후송 stance vs 대기 stance 보존 차이
- outcome: 선택 기록, accuracy 없음
- 특별 distortion: 확률→필연, 과거 사례→현재 불가능, 정기편→모든 편, 의료 능력 일반화

### exile

- fact predicate: 개체/집단 범위와 source를 필수 슬롯으로 둠
- primary comparison: 자기 입장에 불리한 팩트의 보존 차이
- outcome: 선택 기록, accuracy 없음
- 특별 distortion: 전체 집단 일반화, 미상 행위자 채움, 상관→인과, 피해→폐업 인과, 미사용 조항→즉시 실행 가능
- 윤리 평가: 사람/독립 리뷰어

### award

- fact predicate와 chain evaluator 분리
- 각 chain은 `true/false/unknown/blocked` 유지
- surface impression과 normative score 분리
- 결격·부문·항목 비교·최종 선택을 순차 평가
- `award`와 `award_flat`은 `(issue_id,fact_id)`로 구분
