## 8. prun 조건 폼 .why

**옛:**
```
<p class="why">에이전트 1 + 고정 각본 상대. 가치 절반을 부여하고 압박을 반복하면
       <b>어떤 가치 카테고리의 주장이 먼저 사라지는가</b>, 그리고 최종 선택이 자기 가치와
       어긋나게 뒤집히는가를 잰다. 러너는 experiments/pressure_category/run_pressure.py —
       콘솔은 부르고 <b>읽기만</b> 한다. 설계·판정 기준은 같은 폴더의 PREREG_v0.md.</p>
```
**새:**
```
<p class="why">AI 하나에게 시나리오(상황 + 선택지 2개 + 사실 목록 — 카테고리마다 같은 수의 사실, 보통 2개)와 가치 세트(“너에게는 이 카테고리들이 중요하다”는 문장 — 기본 제공 A·B는 시나리오 카테고리를 절반씩 나눠 집는다)를 주고,
       상대 역할은 미리 써 둔 대본(압박 각본)대로 라운드마다 말하게 한다 — AI가 뭐라 하든 대사는 바뀌지 않는다(기본 제공 C0·C1·C2는 세 라운드 같은 문장). 이렇게 하고 라운드마다 압박하면
       <b>어떤 카테고리의 사실이 수첩(AI가 라운드마다 다음 라운드의 자기에게 남기는 500자 메모 — 다음 라운드에는 이것만 기억으로 남는다)에서 먼저 사라지는가</b>,
       그리고 최종 선택이 자기 가치와 다른 쪽으로 가는가를 잴 수 있다. 실험을 실제로 돌리는 프로그램(러너)은 experiments/pressure_category/run_pressure.py —
       이 화면은 러너를 부르고 결과를 <b>읽기만</b> 한다. 설계·판정 기준은 같은 폴더의 PREREG_v0.md(사전등록 문서).</p>
```

## 20. prun 일괄 .why

**옛:**
```
<p class="why">고른 시나리오를 <b>순차 큐</b>로 러너에 하나씩 넘긴다(동시 실행은 여전히 1개 —
       비용 사고 방지). 재료·러너 파일은 무수정, 반복만 콘솔이 맡는다. 가치 세트는 내장 A·B 에
       더해 <b>등록 세트(✎ ALL 류)까지</b> 걸 수 있다 — 단, 방향 각본(C1·C2 류) × 정렬 불명
       세트 조합은 러너가 거부하므로 견적 단계에서 자동으로 빠지고 사유가 표시된다.
       중단하면 지금 묶음까지 멈추고 남은 큐가 취소된다(호출 단위 체크포인트 보존).
       이미 결과가 있는 런은 러너가 [skip] 하므로, 끊긴 일괄을 같은 조건으로 다시 걸면 이어서 돈다.</p>
```
**새:**
```
<p class="why">고른 시나리오를 <b>차례로 하나씩</b> 러너에 넘긴다(동시에 도는 실행은 여전히 1개 —
       비용 사고 방지). 시나리오 파일과 러너는 손대지 않고, 되풀이만 콘솔이 맡는다. 가치 세트는 기본 제공 A·B 에
       더해 <b>직접 등록한 세트(✎ 표시)까지</b> 걸 수 있다 — 단, 방향이 있는 각본(같은 편 압박 C1·반대 압박 C2 등) × 가치가 미는 답이
       없는 세트(건너뜀 이유에는 ‘정렬 불명 세트’로 표시) 조합은 러너가 거부하므로 예상 단계에서 자동으로 빠지고 이유가 표시된다.
       중단하면 지금 도는 묶음까지 멈추고 남은 묶음이 취소된다(AI 호출 한 번 단위의 중간 저장은 남는다).
       이미 결과가 있는 판은 러너가 건너뛰므로([skip]), 끊긴 일괄을 같은 조건으로 다시 걸면 이어서 돈다.</p>
```

## 29. prun 각본 등록 .why

**옛:**
```
<p class="why">압박의 <b>문면과 타이밍</b>이 이 실험의 조작 변수다. 라운드마다 다른 대사
       (점증 압박)도, 첫 라운드부터 미는 것도 가능. 등록은 <b>새 이름으로 추가만</b> —
       기존 각본은 고칠 수 없다(과거 런과의 대응 보존). 대사에 <code>{TARGET}</code>(미는 쪽)·
       <code>{OTHER}</code>(반대쪽) 자리를 쓰면 가치 세트에 맞춰 자동으로 채워진다.</p>
```
**새:**
