시나리오 고르기

실험을 돌리기 전에 "이 시나리오가 무엇을 묻고, 누가 무엇을 아는가"를 확인한다. 여기서 고른 시나리오가 설정·실행 탭에도 함께 선택된다.

원문

시나리오를 고르세요

팩트

에이전트들이 나눠 갖는 원자 사실들. unshared는 일부만 아는 것이고, 그것이 취합의 대상이다.

—

누가 무엇을 아는가 (배분)

에이전트 × 팩트 격자. 히든 프로필이 성립하려면 어느 한 명도 혼자서는 답을 완성할 수 없어야 한다.

—

에이전트 수 바꾸기 — 변종 만들기

에이전트 수는 설정이 아니라 배분표가 정한다(엔진이 배분표에서 읽는다). 그래서 수를 바꾸는 것은 배분표를 새로 만드는 일이고, 같은 이슈 이름 아래 배분표를 갈아치우면 그 이슈로 돌린 과거 run 들이 어떤 배분이었는지를 잃는다. 그래서 원문·팩트를 새 이름으로 복사하고 배분표만 새로 만든다 — 원본은 그대로 남는다.

LLM 호출 0 · 파일 3개(원문·팩트·배분표)가 새 이름으로 생깁니다.

설정

설정 사전(EXPERIMENT_SETTINGS_v0.md) 8축을 그대로 폼으로 옮긴 것. 고른 값은 configs/console/<run_id>.yaml 로 저장되고, 그 파일의 sha256 이 로그의 run_meta 에 찍힌다 — 산출물이 자기 조건을 안다.

팩트 생존 (FAR) — 채점

수첩 매트릭스는 기억에 무엇이 남았나를 보여준다. FAR 은 발화에서 팩트가 살아남았나를 센다 — 다른 관문이라 둘 다 필요하다. 채점은 팩트 × 라운드 × 표 수만큼 호출하므로 자동이 아니라 버튼이다.

run 을 고르세요

개입 창

수첩에서 특정 팩트를 지우고 최종 폴링만 다시 돌린다 — 결론이 바뀌면 그 팩트가 결론을 지탱했다는 인과 증거. 개입 run 은 새 run_id 로 나가고 origin=intervention 이 붙어 집계에서 기본 제외된다(습관이 아니라 필드).

API 키가 필요한 실호출입니다 (에이전트 수만큼 1콜).
