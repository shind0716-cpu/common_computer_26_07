## 1. 목표 한 줄

## 2. 작업 환경

- 리포 루트에서 **git worktree**로 격리한다. 본 작업 폴더는 건드리지 않는다.
  ```

  ```
  `[민옥 결정]` 브랜치 이름: 기본값 `console-final-2026-09-03`.
- 작업은 전부 그 worktree 안에서. main/원 폴더로 merge·push 하지 않는다. merge는 민옥이 한다.

## 3. 단계와 순서 (이 순서를 바꾸지 마라 — 단계마다 커밋 1개)

### 0단계 — 기준선 잡기 (아무것도 고치기 전에)
1. `python -m pytest tests/test_console.py tests/test_console_gates.py -q` 통과 확인.
   실패하면 **여기서 멈춘다**(§8).
2. 서버를 띄우고 §7의 스크린샷 스크립트로 11탭 전부 "전" 스크린샷을 찍는다.
   → `tools/console/_review/before/<탭id>.png`
3. 브라우저 콘솔 에러 수를 기록한다(기준선).
4. 커밋: `console: 0단계 기준선 스크린샷`

### 1단계 — 말 바꾸기 (표시층만)
독자 기준: **이 프로젝트도 실험 배경도 모르는 사람이 읽고 이해할 수 있는가.**

- 대상: index.html의 모든 사람이 보는 글자 — 탭 이름, h2, `.why` 설명 문단, 라벨,
  버튼, 툴팁, 표 머리글, 상태 문구, JS 안 문자열(`PL_KO` 같은 표시용 사전 포함).
- 규칙:
  1. **데이터 키·API 필드·파일명·config 키는 절대 바꾸지 않는다.** 예: 라벨 값
     `진짜뒤집힘`·`면전순응`·`순풍시작`·`완전저항`·`진동/판정불가`·`절충이행`은 JSON/CSV의
     키다. 화면에 보이는 말은 표시용 사전(`PL_KO` 같은 곳)에서만 바꾼다.
  2. 영어 약어·기호는 첫 등장에 풀이를 붙이거나 풀어쓴다. FAR, C0/C1/C2, rep, dry/live,
     run_id, carrier, A/B, persona 전부 해당. 풀이를 못 쓰겠으면 그 말을 쓰지 말고 §9에 적는다.
  3. **뜻을 바꾸지 마라.** 설명 문단(`.why`)에는 실험 설계의 이유와 주의(⚠)가 들어 있다.
     쉬운 말로 다시 쓰되, 숫자·조건·경고는 하나도 빠뜨리지 않는다. 확신이 없는 문장은
     **그대로 두고** §9의 "못 바꾼 문장" 목록에 넣는다. 잘못 쉬운 말 > 어려운 원문 보존이다.
  4. 새 전문용어·비유어를 만들지 마라. 일상어로 풀어라.
  5. 권장: 바꾼 말에는 `title="구: 뒤집힘"`처럼 옛 이름을 툴팁으로 남긴다 — 옛 문서·파일명과
     대조할 팀원을 위해서. `[민옥 결정]` 기본값: 남긴다.
- 참고(강제 아님): 9/2 보고서가 쓴 말 — 결정까지 바뀜 / 말만 바뀜 / 처음부터 같은 편 /
  안 바뀜 / 왔다갔다, 가치(항목 3개 집는 문장 A/B) / 원칙(규칙 6개) / 신념("나는 ~이다" 라벨).
  더 쉬운 말이 있으면 그걸 써도 된다. 단 같은 것을 두 탭에서 다른 말로 부르지 마라.
- 커밋: `console: 1단계 표시 문구 쉬운 말로`

### 2단계 — 배치 바꾸기 (기능 변경 0)
1. **안내 탭 신설, 첫 화면으로.** 내용: 이 콘솔이 뭔지 세 줄 / 트랙별 "무엇을 보는 탭인지"
   한 줄씩 / 압박 실험의 흐름 그림 한 장(시나리오 → 가치·압박 조건 → 실행 → 결과 → 집계,
   인라인 SVG 또는 HTML) / 자주 쓰는 말 풀이 10개 안팎 / "처음이라면 이 순서로" 3단계.
   `[민옥 결정]` 안내 탭을 기본 첫 탭으로: 기본값 예.
2. **압박 트랙을 앞으로.** 탭 순서: 안내 · 압박 실행 · 압박 결과 · 압박 집계 · 발표 모드 ↗ ·
   [보관 ▸].
3. **토론·단독 7탭은 "보관" 그룹으로 접는다.** 펼치면 7탭이 나오고, 각 탭 위에
   "이 화면은 7~8월 실험용이며 지금은 기록으로 남긴 것" 한 줄 띠를 단다. **라우트·기능·JS는
   그대로.** 접힘 상태는 localStorage에 기억해도 되고 안 해도 된다.
4. 커밋: `console: 2단계 안내 탭·압박 우선·보관 그룹`

### 3단계 — 결과가 눈에 들어오게 (압박 결과·집계 탭만)
- 숫자만 있는 표에 뜻이 보이게: 비율 칸에 옅은 막대(배경 그라데이션)나 색 힌트, 범례,
  "이 표가 답하는 질문" 문장 유지.
- 색 규칙: 색 하나 = 뜻 하나. 담화 라벨 색(`PL_COLOR`)은 이미 있으니 그걸 집계·상세·
  격자에서도 **같은 색**으로 쓴다. 빨강·초록만으로 구분하지 말고 글자나 기호를 같이 둔다.
- 빈 상태·로딩 상태 문구: "탭에 들어오면 불러옵니다…" 류를 "무엇을 어디서 읽고 있는지"가
  보이게. 데이터가 없으면 "왜 없는지·어떻게 만드는지" 한 줄.
- 표는 가로 스크롤 컨테이너 안에서만 넘치게(페이지가 옆으로 안 밀리게).
- **집계 산식·필터·정렬 로직은 손대지 않는다.** 보이는 방식만.
- 커밋: `console: 3단계 압박 결과 가시화`

### 4단계 — 모양 다듬기 (CSS)
- 기존 `:root` 색 토큰·글꼴 유지. 새 팔레트 만들지 마라. 취향 작업이 아니라 **일관성** 작업이다.
- 할 것: 간격·글자 크기 체계 통일, 버튼 종류 셋(실행/보조/위험)으로 정리, 인라인 style을
  클래스로 이동, 1024px 이하에서 깨지는 곳 최소 보정, 포커스 표시, 긴 표 헤더 고정.
- 하지 말 것: 다크 모드, 애니메이션, 프레임워크 도입, 파일 분리(index.html 한 파일 유지).
- 커밋: `console: 4단계 CSS 일관성`
