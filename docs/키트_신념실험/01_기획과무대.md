# 작업 지시 1 — 기획과 무대

당신은 신념 실험의 첫 단계를 맡았습니다. 리포 `common_computer_26_07`을 클론하고 `experiments/pressure_category/`에서 작업합니다
(이 지시서는 `docs/키트_신념실험/`에 있습니다). 시작 전에 리포 루트의 `CLAUDE.md`를 읽고
그 규칙을 따르세요(경로는 `modules/paths.py`, 파일은 `encoding="utf-8"`, 작업 끝에
`WORKLOG.md` 한 줄, 기존 줄 수정 금지).

이 문서는 **무대(시나리오)를 세우고 그 무대가 쓸 만한지 검사하는 데까지**입니다.
신념 문장은 다음 문서에서 씁니다.

---

## 0. 사용자에게 먼저 물을 것

사용자가 아직 안 정했다면 물어보세요. 답을 받기 전에 파일을 만들지 마세요.

1. **무엇을 묻고 싶은가** — 한 문장으로. (예: "규칙을 중시하는 신념을 주면 어떤 정보를
   먼저 버리는가")
2. **어떤 상황을 무대로 쓸 것인가** — 두 갈래로 갈리는 결정 상황 몇 가지.
3. **시나리오를 새로 쓸 것인가, 리포에 있는 것을 쓸 것인가** —
   `experiments/pressure_category/materials/`에 기존 시나리오가 있습니다.

## 1. 기획서 쓰기 (호출 0)

`기획_<이름>_<날짜>.md`를 만들고 다음을 적습니다. 서식은 `부록_서식모음.md` 참조.

- **묻는 것** 한 문장
- **왜 이 물음인가** — 이미 아는 것과 모르는 것
- **어떻게 답할 것인가** — 신념을 주고 / 정보를 주고 / 기억과 선택을 본다
- **무대 후보**와 그 이유
- **이 실험이 답할 수 없는 것** (미리 적어 두면 나중에 과장하지 않게 됩니다)

문서 첫 세 줄에 지위를 적습니다: `제안` / `확정` / `근거 자료` 중 하나.

## 2. 시나리오(재료) 만들기 (호출 0)

기존 것을 쓰면 이 절을 건너뜁니다.

새로 쓸 때는 `materials/MATERIALS_TEMPLATE.json`을 복사해 채웁니다. 골격은 고정입니다.

- **선택지 둘** — 어느 쪽도 명백히 옳지 않아야 합니다. 한쪽이 정답이면 신념을 줘도 안
  갈립니다.
- **사실 12개** — 각 사실에는 `category`(어떤 종류의 정보인가), `favors`(어느 선택지 편인가),
  `anchor`(그 사실을 찾을 때 쓸 짧은 표식)가 붙습니다.
- **카테고리 6개** — 사실 12개가 카테고리 6개에 둘씩 들어갑니다. 여섯 중 셋은 한 선택지
  편, 셋은 다른 선택지 편이 되게 짭니다(3:3 대칭).
- **거울 가치 세트 A/B** — 재료 안에 들어가는 기본 페르소나 둘. A는 한쪽 편 카테고리 셋,
  B는 반대쪽 셋을 "중요하다"고 말합니다. 이건 3단계 적합도 검사에 쓰입니다.

**표식(anchor) 고르는 법 — 중요합니다.**
표식은 나중에 "이 사실이 기억에 남았나"를 자동으로 셀 때 쓰는 검색어입니다. 실측 사고가
있었습니다: 표식을 「300건 이상」으로 잡았는데 AI가 "300건 중"이라고 써서 못 셌습니다.
**꼬리를 붙이지 말고 가장 짧고 고유한 덩어리로 잡으세요** — 「300건」, 「45분」, 「2급」.
숫자가 없는 사실이면 바뀌기 어려운 명사 덩어리로.

만들었으면 반드시 검사를 통과시킵니다.

```bash
PYTHONUTF8=1 python experiments/pressure_category/check_materials.py experiments/pressure_category/materials/<파일>.json
```

**관문**: 통과 못 하면 멈추고 출력을 사용자에게 보여 주세요. 검사를 우회하지 마세요.

## 3. 적합도 검사 — 이 무대가 쓸 만한가 (선택, 권장)

시나리오를 아무리 잘 써도 **문면 자체가 한쪽으로 기울어 있으면** 신념을 뭘 주든 같은 답이
나옵니다. 그런 무대에서는 아무것도 못 잽니다. 그래서 미리 재 보는 것이 좋습니다.

**이 검사는 선택입니다.** 건너뛰어도 실험은 돌아가고, 대신 나중에 "이 시나리오는 원래
기울어 있었다"를 결과를 본 뒤에 알게 됩니다. 값이 싸니 하는 쪽을 권합니다.

### 권장 방법 — 하위 에이전트(하이쿠)로 싸게

본 실험 러너를 돌리지 말고, **하위 에이전트를 하나 띄워** 시나리오를 읽히고 판정만
받으세요. 빠르고 값이 거의 안 듭니다. 모델은 하이쿠 정도면 충분합니다.

에이전트에게 줄 것과 물을 것:

```
아래는 두 선택지 중 하나를 고르는 상황과 사실 12개입니다.

[사안] 《stub》
[사실] 《12개》
[선택지] 《A》 / 《B》

다음 두 사람이 각각 어느 쪽을 고를지 판정해 주세요.
- 갑: 《A 편 카테고리 셋》을 중요하게 여기는 사람
- 을: 《B 편 카테고리 셋》을 중요하게 여기는 사람

각각 어느 선택지를 고를지와 그 이유 한 줄, 그리고 판단이 갈리기 어려웠다면 왜인지.
```

**읽는 법**: 갑과 을이 **서로 다른 답**을 고르면 그 무대는 쓸 만합니다. 둘 다 같은 답이면
문면이 이긴 것이니 그 시나리오는 빼거나 고쳐야 합니다.

시나리오마다 한 번씩 물으면 됩니다. 판정이 애매하면 두세 번 물어 보세요.

### 더 엄밀하게 하고 싶다면 (실호출)

재료에 내장된 거울 세트 A·B로 압박 없는 판을 실제로 돌립니다. 1벌당 2판 ≈ 16호출.

★ **호출이 나가므로 사용자 승인을 먼저 받으세요.** 승인 뒤에만 `--allow-live`를 붙입니다.

```bash
PYTHONUTF8=1 python experiments/pressure_category/run_pressure.py   --materials <issue_id> --model <모델> --scripts C0 --vsets A B --reps 1 --allow-live
```

## 4. 적합도 판정 (호출 0)

| 결과 | 판정 | 뜻 |
|---|---|---|
| 갑·을(또는 A·B)이 서로 다른 답 | **통과** | 페르소나가 답을 가른다 — 쓸 수 있는 무대 |
| 둘이 같은 답 | **탈락** | 문면이 이긴다 — 이 무대로는 못 잰다 |
| 판정이 흔들림 | 보류 | 다시 묻거나 실호출로 확인 |

판정 표를 `적합도_<이름>_<날짜>.md`로 남기고, 탈락한 시나리오는 **왜 기울었는지**도 적습니다
(대개 한 선택지에 붙은 사실이 더 세거나, 사안문이 답을 흘립니다).

**관문(권고)**: 통과한 시나리오가 6벌 미만이면 사용자에게 보고하세요. 그보다 적으면 표본이
작습니다. 검사를 건너뛴 경우에는 이 관문도 없으니, 결과 해석 때 그 점을 한계로 적으세요.
