# 팀 메모리 사용 지침 (Claude용)

이 문서는 팀원 각자의 Claude에게 주는 공통 지침입니다.
Claude Code 사용자는 프로젝트 저장소 루트에 이 파일(CLAUDE.md)을 두면 자동으로 적용되고,
claude.ai(웹/앱) 사용자는 프로젝트의 지침(instructions)에 이 내용을 붙여넣으면 됩니다.

## 우리 팀의 기록은 한 곳에 있다

- 팀 메모리 (색인): https://app.notion.com/p/39e0261412b08051bb6bd6178e7aeac3
- 구조: 메인 페이지 = 색인(한 줄 블록들), 하위 페이지 = 전문(무손실 기록)
- 색인은 요약이 아니라 주소다. 전문을 대체하지 않고 가리키기만 한다.

## 세션 시작 시 (읽기)

1. 위 색인 페이지를 읽는다.
2. 전체를 다 읽을 필요 없다 — 최근 주차 섹션의 블록들을 훑고,
   지금 작업과 관련된 블록만 전문(하위 페이지)으로 내려가 읽는다.
3. 색인이 길어져도 절대 요약본을 만들어 대신 쓰지 않는다.
   필요한 건 "최근 N블록 + 관련 전문"이지 전체 요약이 아니다.

## 작업을 마쳤을 때 (쓰기)

1. 색인 페이지 하위에 전문 페이지를 만든다.
   - 제목: `YYYY-MM-DD | 이름 | type | 핵심 주제`
   - 양식은 "📝 전문 작성 템플릿" 하위 페이지를 따른다
     (한 일 / 확정된 것 / 막힌 것·열린 질문 / 링크)
2. 색인 페이지의 현재 주차 섹션 맨 아래에 한 줄을 추가한다.
   - 형식: `[YYYY-MM-DD | 이름 | type] 핵심 한 줄 → 전문 링크`
   - type: decision(확정된 결정) / result(작업 결과) / blocker(막힌 것) / question(열린 질문)
3. 색인 줄의 "이름"은 이 Claude를 쓰는 팀원 본인의 이름이다.

## 지켜야 할 규칙 3개

1. **Append-only** — 과거 블록을 수정·삭제하지 않는다. 정정은 새 블록으로.
2. **본인 색인** — 자기(자기 사용자)가 한 작업만 색인에 올린다.
   남의 작업을 대신 정리하거나 색인해주지 않는다.
3. **재요약 금지** — 기존 기록들을 합쳐 요약본을 만들지 않는다.
   요약이 원본을 대체하는 순간 정보 손실이 시작된다 —
   이 팀이 연구하는 바로 그 현상(factual attrition)이다.

## 주의사항

- 전문에 "확정된 것"이라고 적는 것은 개인/작업 단위의 확정이다.
  팀 합의는 주간 동기화에서 소리 내어 확인된 것만 인정한다.
  이 창구는 상태 공유 채널이지 의사결정 채널이 아니다.
- 색인 페이지의 상단 규칙 영역과 팀 프로필 섹션 구조는 바꾸지 않는다.
  Claude가 편집하는 곳은 "색인의 주차 섹션(줄 추가)"과
  "새 전문 하위 페이지 생성" 두 곳뿐이다.

## 최초 1회 셋업 (사람이 할 일)

1. claude.ai → 설정 → 커넥터 → Notion 연결.
   OAuth 화면에서 팀 워크스페이스를 선택하고, 팀 메모리 페이지 접근을 허용한다.
2. 연결 후 Claude에게 "팀 메모리 색인 읽어줘"라고 시켜서 접근을 확인한다.
3. 팀 프로필 섹션에서 자기 페이지 제목을 본인 이름으로 바꾸고 내용을 채운다.
   (W1 첫 과제)
