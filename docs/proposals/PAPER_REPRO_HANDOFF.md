## 1. 무엇을 재는가 — 결과 변수 사전 고정

착수 전에 박는다. **돌려보고 나서 정하면 그 수치는 근거가 아니다.**

| 층 | 지표 | 산출 위치 |
|---|---|---|
| 표제 (H1) | 항목별 `far_by_stage[0]`(대화 없음) vs `[마지막]`(토론 후) | judgment.summary |
| 보조 | `far_critical` 같은 대조 | judgment.summary |
| 정답 (신규) | `gold_label` 대비 최종 판단 일치율 | 본 작업 범위 **밖** |

- **논문 대조점**: 대화 없음 19% vs 토론 68%. 우리 파이프라인은 이 둘을 **한 판 안에서**
  낸다(`far_by_stage`의 r0 와 마지막). H1 에 팔 두 개가 필요 없다.
- **단위는 항목(issue)이다.** 팩트를 전체 풀에 합쳐 하나의 비율을 내지 말 것 —
  항목 간 편차가 사라져 신뢰구간이 거짓으로 좁아진다.
- 이 표에 없는 지표를 사후에 추가해 결론으로 삼지 않는다.

## 2. 파킹 — 지금 다루지 않는 것

**부활(resurgence)은 "소실 팩트 재주입 효과"로 간주하고 이번 설계에서 뺀다.**

근거(2026-08-10 전수조사): 판정물 6개 전체에서 소실→생존 전이 2건, **둘 다
`h2p_v0`의 `ledger_inject`(r3, `reason=v0_all_missing`)와 같은 라운드**였고
재주입 없이 되살아난 칸은 0건이었다. `access_window`의 `resurgence` 지표(2건)는
**둘 다 라운드 0**이라 정의상 "비보유 발화"이지 부활이 아니다.

**재개 조건** — 아래 중 하나가 나오면 파킹을 푼다:
1. 재주입 없는 라운드에서 소실→생존 전이가 관측된다.
2. `access_window`의 `resurgence`가 **라운드 0이 아닌 곳**에서 나온다.
3. 표본이 커져 사건 수가 두 자릿수가 된다(그때 하위 분류가 성립).

집계 시 `resurgence`는 **"창 계산이 틀린 비율의 하한"**으로만 읽는다(모듈 자기 진단 문면).

## 5. 지어야 할 것 — 모듈 3개

### 5-1. loader: 원본 → `issues/`

저자 대응물 없음(저자는 `datasets/*.json`을 그대로 읽는다). 우리 계약으로 옮기는 순수 변환.
**LLM 호출 0.**

매핑:
```
background            -> body
title                 -> title
question              -> question       (D3 결정에 따름)
"paper"               -> source
{url: null, fetched_at: <적재 시각>, usage_approved: null,
 origin_id: <원본 id>}  -> source_meta
{label, scores}       -> gold           (계약 밖 — §7 참조)
```
- `issue_id`는 **순번제** `issue_ethics_0001` … 로 만든다. 원본 id
  (`ethics-scruples-tb6yl5VD…`)는 길고 대소문자가 섞여 파일명에 부적합하며,
  `source_meta.origin_id`에 보존한다.
- 필수 키(validate): `schema_ver · issue_id · source · title · body`.

### 5-2. extractor: `issues/` → `facts/`

**저자 `facts.py`를 3단계 그대로 계승한다.** 줄이면 재현이 아니고 늘릴 이유가 없다.

```
facts_initial  (background)                       -> raw_facts
facts_refine   (background + raw_facts)           -> refined_facts
facts_select   (question + refined_facts)         -> important_facts (bool 목록)
```
- 프롬프트는 **저자 저장소 원문을 직접 읽는다** — `modules.authors_prompts.load()`.
  복사본을 만들지 말 것(리포 정책이자 이번 대조가 가능했던 이유).
- 모델·온도는 D1 결정에 따른다. 저자 원값은 gpt-5 / temp 0 / n=1.

계약 매핑:
```
refined_facts[i]     -> facts[i].text
important_facts[i]   -> facts[i].critical
[]                   -> facts[i].tags      (저자에 대응물 없음 — §7)
생략                  -> facts[i].prior     (validate 필수 아님)
f"fact_{n:02d}"      -> facts[i].fact_id
{model, temperature, prompt_ver}  -> extractor
```
- 팩트마다 필수 키: `fact_id · text · tags · critical`.
- **`raw_facts`를 버리지 말 것** (규약 8). `extractor.raw` 또는 별도 원자료 파일에 보존.
- **LLM 응답 원문을 그대로 남길 것** (규약 5). `obtain_json` 파싱 결과만 저장 금지.

### 5-3. perspective: `facts/` → `assignments/`

**저자 `perspective.py`를 계승한다.** 저자의 "perspective" = **팩트 부분집합 그 자체**이며,
우리가 쓰던 문자열 라벨과는 다른 물건이다.

```
prompts/perspective.txt  <===facts===>  <- "{index} (Important|Not Important): {text}"
-> JSON [[fact_idx, ...], x4]
```

저자 프롬프트가 스스로 거는 규칙(산출물이 지켰는지 **계수해서 보고**할 것 — 판정 말고 계수):
관점 4개 · 관점 내 논리 일관 · **어떤 관점도 전 팩트 보유 금지** · 모든 팩트가 최소
1관점에 등장 · 겹침 허용 · **중요 팩트는 각 관점에 포함** · 원문 순서/인접성 기반 그룹화 금지.
저자 `discussion.py`의 `check_available`은 `len(pers) != 4`면 그 항목을 **건너뛴다** —
같은 규칙을 따르고, 건너뛴 항목 수를 반드시 보고할 것(조용한 누락 금지).

계약 매핑 — **관점 4 × 입장 2 = 8 에이전트, 같은 관점의 두 사람은 팩트가 동일**:
```
agents[2k]   = {agent_id, perspective: f"관점{k+1}", stance: "pro", assigned_fact_ids: G_k}
agents[2k+1] = {agent_id, perspective: f"관점{k+1}", stance: "con", assigned_fact_ids: G_k}
```
> 이 "쌍이 같은 팩트" 조건이 **현행 드리프트를 고치는 자리**다. 실측: 우리
> `assignment_issue_esa.json`은 관점 쌍 4개 중 두 사람 팩트가 같은 쌍이 **0개**다.
> 저자는 `for item in perspective: ...; out.append(yes); out.append(no)` 로 같은
> `fact_text`를 쓴다(`discussion.py:74-79`).

- `seed`는 필수 필드인데 저자 관점 생성은 LLM(temp 0)이라 seed 개념이 없다 →
  **`seed: 0`** 으로 두고 결정론 근거(모델·temp 0·프롬프트 지문)를 `created_by`에 적는다.
- 필수 키: `schema_ver · issue_id · seed · agents`.

## 6. 표본 설계 — 순차

**항목별 FAR 편차를 우리는 아직 모른다**(이슈가 ESA 하나뿐이라 추정할 데이터가 없다).
따라서 필요 표본을 지금 확정하지 않고 단계로 나눈다.

1. **추출은 넉넉히 (150~200건).** 추출 4콜/건이라 800콜이며 **모든 팔이 공유하는 1회
   비용**이다. 발화·판정은 64콜/건 × 팔마다 반복이므로, 비싼 건 뒤 구간이다.
   추출을 넉넉히 하면 나중에 표본을 늘릴 여지를 싸게 산다.
2. **발화·판정은 먼저 15~20건만.** 여기서 **항목당 FAR의 실제 표준편차를 잰다.**
3. 그 SD로 필요 표본을 재계산한다. 대응 설계 기준 `n ≈ 8/d²` — 표제 효과(49pp)는
   한 자릿수, 0.10 차이는 약 50건, 0.05 차이는 약 200건.

표본 선정:
- **층화**: `gold_label` NO 394 / YES 316 비율을 유지한다.
- **무작위 + 시드 고정**, 선정 시드와 **뽑힌 `issue_id` 목록 전체를 산출물에 기록**한다.
- **앞에서부터 자르지 말 것.** `news_raw`가 이미 "앞에서부터 순서대로" 뽑힌 편향을
  갖고 있다 — 우리까지 같은 짓을 하면 편향이 겹친다.

## 7. 계약 밖 필드 2건 — 임시 처리와 사유

| 필드 | 임시 처리 | 왜 |
|---|---|---|
| `gold`(정답) | `issues/`에 `gold{label, scores}`로 실어 둔다 | 계약에 자리가 없다. 히든 프로필 노드의 "정답 필드 신설(민옥 소관)"이 여기서 실제로 필요해졌다. 추출·배분은 정답을 안 쓰므로 이번 작업을 막지 않는다. **버리는 것만은 금지**(규약 8) |
| `tags` | 빈 배열 `[]` | 팩트마다 필수인데 저자 산출에 대응물이 없다. 우리 `condition\|exception\|…` 분류는 수작업 산물이라 저자 트랙에 없다. 억지로 LLM에 태그를 시키면 논문에 없는 단계가 늘고 비용도 는다 |

둘 다 **계약 변경이 아니다.** 확정은 보드 소관이며 이 문서는 임시 처리만 정한다.

## 10. 완료 기준 (이걸 다 만족해야 완료)

1. 표본 N건의 `issues/`·`facts/`·`assignments/`가 생성되고 **전건 `validate` 통과**.
2. 관점 배분이 **저자 규칙 검사를 통과**하고, 위반·건너뜀 항목 수가 보고된다.
3. **관점 쌍 전부에서 두 사람의 `assigned_fact_ids`가 동일**함이 수치로 확인된다.
4. 표본 선정 시드와 `issue_id` 목록이 산출물에 남는다.
5. LLM 응답 **원문**이 전건 보존된다(파싱 결과만 저장 금지).
6. 편차 대장(§4 출처 편차 · D1 모델 · D2 언어 · 라이선스 미확인)이 README에 적힌다.
7. `WORKLOG.md` 끝에 한 줄 추가(규약 6, 기존 줄 수정 금지).

## 12-1. 사전 규칙과 판정

| 질문 | 사전 규칙 | 실측 | 판정 |
|---|---|---|---|
| **Q0** gpt-5 접근 | 1콜 확인 | 응답 `OK` | **접근 가능** — Q1 은 제약이 아니라 선택 |
| **Q1** 추출 모델 | 팩트 개수 중앙값 ±1 **AND** critical 비율 ±10%p → mini | 개수 중앙 **13 vs 17 (차 4)** · critical 0.844 vs 0.862 (차 1.8%p) | **gpt-5** (개수 규칙 위반) |
| **Q2** 질문 언어 | 팩트 단위 일치율 ≥0.9 → 한국어 유지 가능 | **60/64 = 0.938** | **한국어 유지 가능** |
| **Q3a** 질문 형태 | 측정 후 사유와 함께 기록 | 영어획일↔제목 **61/64 = 0.953** | **항목별 제목** 유지(차이 없음도 함께 기록) |

- **Q1 상세**: mini 가 5건 **전건에서 더 많이** 뽑았다(+2~+9). `facts_refine` 압축률이
  gpt-5 ~0.42 vs mini ~0.47. 팩트 수는 **FAR 의 분모**라, 모델이 다르면 값이 비교
  불가능해진다. critical **비율**은 거의 같으므로 갈린 것은 "무엇이 중요한가"가 아니라
  "몇 개로 쪼개는가"다.
- **Q2·Q3a 상세**: `refined_facts` 를 고정하고 `facts_select` 만 갈아 끼운 정확 비교다.
  세 질문 후보가 모두 0.94~0.95 로 붙었다 — **질문 문자열은 이 단계에서 결과를 거의
  바꾸지 않는다.** 착수 전 예상("항목별 제목은 정보량이 많아 달라질 것")은 **기각**됐다.
