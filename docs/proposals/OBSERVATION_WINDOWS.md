# 관측 창 인벤토리 — "발화 밖에서 사실이 남아있는가"를 보는 4개의 창

작성: 요한 측 (2026-07-28) · 지위: **개인 제안 — 동기화(민옥·요한) 안건 재료**. 확정은
사람 몫이며, ③·④ 창은 민옥 담당 파일과 접속되므로 여기서는 제안까지만 한다.

사람용 세 줄: ① 외부 리뷰(7/28)의 핵심 지적 — "낮은 TSR을 전달 실패라 부르면, 말함만 재고
앎을 결론낸 논문의 오류를 우리가 반복한다"를 받아들여, 사실의 생존을 발화 밖에서 보는 창을
전수 점검했다. ② 창은 4개다: 발화(완비) · 접근(이번에 지음) · 회고(반쪽) · 사용(공백).
③ 접근 창 실측에서 "말이 끊기면 정확히 1라운드 뒤 시스템에서 물리적으로 소멸"이 확인됐다 —
남은 건설 2건(회고 창 정비·사용 창 신설)은 민옥 님 소관과 접속되는 동기화 안건이다.

## 1. 왜 — 리뷰가 찌른 곳

우리 실측 보고("TSR 10~24%")가 "전달 실패"로 인용되는 순간, 우리는 FOL-8(말함을 재고 앎을
결론)의 거울상 오류를 범한다. 정보는 재발화 없이도 전달될 수 있다(듣고 기억함·판단에 반영).
→ 처방은 지표 추가가 아니라 (a) 해석 사거리의 사전 고정, (b) 발화 밖 관측 창의 건설이다.
(a)는 P3_TRANSMISSION_DESIGN.md 7/28 append(해석 한정 3조)로 완료. 이 문서는 (b)의 지도다.

## 2. 관측 창 4개 — 현재 상태

| 창 | 보는 것 | 계기 | 상태 |
|---|---|---|---|
| ① 발화 | 다시 말해졌는가 | FAR·팩트시계·P3 층1(B·TSR) | **완비** |
| ② 접근 | 에이전트 입력에 물리적으로 존재하는가 | prompt_assembly(v0.3) + **modules/access_window.py(신규)** | **완비(서술 계기)** |
| ③ 회고 | 물으면 회수되는가(잠재 보유) | recall.py(민옥) | **반쪽** — 손실 채널 전용으로 정비 필요 |
| ④ 사용 | 판단에 실제로 쓰이는가(기능적 가용) | 결정 과제 | **공백** |

핵심 전제(P3 설계 §2-0): 이 엔진은 롤링 창이라 라운드를 넘는 숨은 내부 기억이 구조적으로
없다. 따라서 "발화 밖 생존"은 심리량이 아니라 **컨텍스트 조립에의 물리적 존재**이고, 그건
로그로 전량 관측 가능하다 — ②가 그 창이다. 외부 리뷰의 "직접 물으니 기억하더라의 애매함
(내부 보유인가, 컨텍스트 재읽기인가)"이 이 생태에서는 발생하지 않는다.

## 3. ② 접근 창 — 이번에 지은 것과 첫 실측

`modules/access_window.py` (P3 부속 서술 계기, 판별표 밖·추가 LLM 0·파일 안 씀):
라운드마다 각 팩트를 **spoken(발화) / accessible(침묵하되 창에 존재 = "은퇴") /
inaccessible(어느 창에도 없음 = "사망")** 로 판정한 상태 원장 + 은퇴 결말·부활 채널 집계.
창 원천은 prompt_assembly(v0.3) 우선, 구 로그는 §2-0 재구성.

dryrun2(issue_esa, 8에이전트·12팩트·4라운드, complete 채널·ledger 없음) 실측:

- 상태 곡선: round0 발화 12 → round3 발화 6 · **접근 생존 12→12→10→6**.
- 최종 사망(inaccessible) **6/12**. 침묵(은퇴) 에피소드 6건 **전부 사망 결말** — 구조 없이
  침묵에서 살아 돌아온 팩트 0, resurgence(접근 없는 발화) 0.
- 침묵 유예 = **정확히 1라운드** (타임라인 전형: SSAD, SADD). w=1 롤링 창의 기계적 귀결이
  데이터로 확인된 것 — "은퇴는 곧장 사망으로 굳는다, 구조(ledger)가 없다면".

해석 한정: 이 창은 "어디에 존재하는가"만 잰다. inaccessible은 판단 활용 실패의 증명이
아니고 accessible은 활용의 증명이 아니다(→ ④ 창의 몫).

## 4. ③·④ 창 건설 제안 (동기화 안건 — 민옥 님 소관 접속)

**③ 회고 창 정비** (recall.py는 민옥 파일 — 협의 요청):
- 적용 조건: complete 채널 비권장·손실 채널 유효(7/28 왕복 합의 계승).
- 강화 2건: (i) replay 대신 **컨텍스트 제거 조건**(원 대화 없이 압축 상태/메모만 제공) —
  "회수"가 재읽기가 아님을 보장. (ii) **검사 사다리**: 비단서 자유회상 → 단서 회상 →
  재인(MC — P3 §7-5의 MC 프로브와 합류). 기존 open/pointed AB에 팔 추가 형태 제안.

**④ 사용 창 신설** (결정 과제 — 4관문 마지막, 계기 공백):
- 최소 설계 = **노출-조건부 사용률**: 비보유자 a가 노출된(X(a,f,r)=1, 층1 좌표 재사용)
  팩트 f를 최종 결정 과제 답변에 반영하는 비율. 층1 원장·②접근 원장과 좌표계가 같아
  신설 인프라가 거의 없다.
- 판정자는 기존 judge 계약(judge_fact 재사용) 범위에서 — 사양 변경 필요 시 보드 안건.
- 이 창이 생겨야 "은퇴 ≠ 사망" 주장의 마지막 고리(기능적 가용)가 실측이 된다. 외부 리뷰의
  사슬: 발화 중단 → 자발적 회수 저하 → **기능적 사용 저하** → 타 에이전트 접근 실패 →
  최종 판단 손실 — 굵은 고리가 ④ 창 없이는 영원히 가설이다.

## 5. 동기화에 올릴 것 (정할 것 3건)

1. ③ recall 정비(컨텍스트 제거 + 검사 사다리)를 민옥 실험 트랙에 편성할지 — 담당·시점.
2. ④ 노출-조건부 사용률의 소유권(4관문 "사용"의 계기) — P3 부속인가 별도 모듈인가.
3. ② access_window의 지위 — 서술 계기 유지(현행) vs 본실험 보조 지표 승격(승격이면
   사전고정 절차 필요).
