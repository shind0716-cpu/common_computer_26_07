# 실험 설정 사전 v0 — 조건을 부르는 말 (초안)

> 작성: 민옥·SilenceBreaker, 2026-07-29. 지위: **v0 — 민옥 승인 (7/29).** 단 §4(돌릴 조합·이름)는 후보 상태로 미정.
> 이 문서가 확정되면: 보드 결정 로그 등재 + 요한 님 `condition` 라벨·template 등록·뷰어 비교 축과 어휘 통일.

## 사람용 세 줄

1. 실험 조건을 부르는 말이 없어서 run 이름(`run001`, `h2p`, `tp1`)에 조건을 욱여넣어 왔다. 이 문서는 **조정 가능한 설정 8개의 사전**과 **실제로 돌릴 조합의 이름**을 정한다.
2. 기존 "장부 사다리(v0→v1→v2)" 프레임을 접는다 — 바꿀 수 있는 손잡이가 여러 개가 된 지금은 한 줄 사다리가 아니라 **설정 조합**이며, 장부는 여러 설정 중 하나로 강등된다(끔/자동재주입 두 값으로 동결).
3. 핵심 신설: **개인 수첩** — 에이전트가 매 라운드 "남길 것"을 500자로 스스로 갱신하는 개인 기억. 손실을 채널(통로)이 아니라 **기억(용량 초과가 강제하는 처리)**에서 모델링한다. 실제 시스템에서 정보가 깎이는 근본 원인이 이것이라는 판단(민옥 7/29).

---

## 1. 왜 이 문서가 필요한가

증상 세 개가 이미 나왔다.

1. **run 이름에 조건이 인코딩되고 있다.** 이름만 봐서는 무슨 조건이었는지 알 수 없다 (요한 측 7/27 문제 제기 — "run_id 이름에 인코딩하는 수밖에 없다").
2. **`ledger_mode` 한 칸에 두 개념이 눌려 있다.** "장부 없이 요약 기록" 같은 조건(요한 7/28 제안)은 장부 설정과 전달 설정이 동시에 움직이는데, 현행 어휘로는 한 단어로 적을 수 없다.
3. **세 갈래 작업이 이 어휘를 기다린다.** 요한 측 `condition` 라벨(v0.3 안건), template 등록(경계 조항 A-3), 뷰어 쌍 비교 축 ③(아키텍처 변주).

용어 원칙 (민옥 7/29): **팀 바깥 사람(이론조)이 바로 알아듣는 말을 쓴다.** "사다리" 같은 은유 대신 "설정", "조합", "수첩" 같은 일상어.

## 2. 설정 사전 (8개)

게임의 설정 메뉴처럼: 실험 1회(run) = 아래 8개 설정에서 하나씩 고른 조합.

| # | 설정 | 뜻 | 값 | 상태 |
|---|---|---|---|---|
| 1 | **받는 말 — 범위** | 몇 라운드 전까지 보이나 | 직전만 / 전부 | 직전만 구현됨 |
| 2 | **받는 말 — 기억** | 개인 수첩을 쓰나 | 수첩 없음 / **개인 수첩 500자** | 수첩은 신설 대상 |
| 3 | **라운드 수** | 대화를 몇 바퀴 도나 | 3 / 10 / … | 있음 (숫자만 변경) |
| 4 | **연결 모양** | 누구와 말을 주고받나 | 전원 / 일렬 / 트리 | 셋 다 있음. **전원을 기본으로 확정** (민옥 7/29) |
| 5 | **입장** | 찬/반을 미리 정해주나 | 찬 / 반 / **없음(협력)** | 찬반만 구현. "없음"은 템플릿 신설 필요 |
| 6 | **성격** | 에이전트 말투·태도 | 기본 / 열린 / 고집 / **직접 추가** | 저자 3종·전원 일괄만 가능. 직접 추가 + 에이전트별 지정은 신설 대상 |
| 7 | **정보 나누기** | 팩트를 누구에게 몇 개씩 주나 | 겹침도 k, 쪼개는 방식 | 수기 1벌뿐. **생성기 신설 확정** (민옥 7/29) |
| 8 | **장부** | 사라진 팩트를 다시 넣어주나 | 끔 / 자동 재주입 | 둘 다 있음. **이 두 값으로 동결** — v1(선별)·v2(조회형)는 만들지 않음 (민옥 7/29) |

### 2-1. 받는 말 — 왜 두 칸인가

둘 다 "남의 말이 나에게 어떤 모습으로 도착하나"의 다이얼이지만, 하나는 **어디까지 담나**(범위), 하나는 **깎이나**(기억)다. 조합 네 칸이 전부 다른 실험이다:

| | 수첩 없음 | 개인 수첩 |
|---|---|---|
| **직전만** | 현행 (논문 세팅) | 손실 채널 본조건 |
| **전부** | 회의록 전체 매번 재독 — 안 깎이는 기준선(비쌈) | (조합 가능, 우선순위 낮음) |

### 2-2. 개인 수첩 — 핵심 신설 (민옥 7/29 설계)

**무엇**: 에이전트마다 자기 수첩 하나. 매 라운드 끝에 "지금까지 알게 된 것 중 남길 것"을 500자 이내로 **스스로** 갱신한다. 다음 라운드 입력 = 배정 팩트 + **자기 수첩** + 이번 라운드에 들어온 말.

**왜 이 자리인가**: 실제 시스템에서 손실의 근본 원인은 좁은 통로가 아니라 **컨텍스트 용량 초과가 강제하는 처리**다(랭체인 요약 메모리, 회사 500자 재귀 블록이 전부 이 산물). 압축을 기억 관문에 두면 손실이 엔진의 인위 설정이 아니라 **에이전트의 행위**가 된다.

**설계 원칙 4개**:
1. **주관성은 관측 대상이지 설계 목표가 아니다.** 관점·팩트가 다르니 수첩이 갈라질 것을 기대하되 강제하지 않는다. 수첩들이 라운드에 걸쳐 **수렴**한다면 그것은 실패가 아니라 발견이다 — 논문이 발화에서 본 동질화의 기억층 판.
2. **수첩 갱신 지시문은 "요약해라"가 아니다.** "이번 라운드 내용을 요약하라"고 시키면 전원이 같은 라운드를 봤으니 수첩이 게시판처럼 수렴한다(민옥 7/29 지적). "**네가 남길 것**을 적어라"로 대상을 자기 판단에 묶는다. 남의 말을 수첩에 실어 나르는 것(중계)은 허용 — 그 선택이 측정 대상이다.
3. **수첩 원문은 로그에 전량 저장** — 재생성 불가 텍스트 전문 저장 조항(스키마 v0.3 A-1)이 그대로 적용된다.
4. **개입 창은 진단 도구다.** 수첩은 조립 명세의 슬롯이므로 "수첩에서 특정 팩트를 지우고 재실행하면 결론이 바뀌나" 같은 인과 개입이 가능하다(민옥 7/29 제안). 단 개입 run은 본실험 수치와 섞지 않는다.

**이 설계가 새로 여는 것 3개**:
- **보유 관문의 직접 관측.** "이 에이전트가 이 라운드에 무엇을 기억에 남겼나"가 텍스트로 보인다. 요한 님 관측 창 4종 표에서 "반쪽"이던 회고 창의 정답지.
- **회고 프로브의 재유효화.** 7/28 동결 논리는 "온전 컨텍스트에선 창 밖이 없다"였다. 수첩 조건에선 창 밖이 실재한다 — 수첩에서 떨어진 것은 그 에이전트에게 진짜로 없다. 동결 해제 조건 충족.
- **회사 접점.** 수첩이 재는 것은 선별 정책(무엇을 남길 것인가) — "criticality 선정은 회사도 안 본다 = 우리 기여의 자리"(동범 7/21)와 정확히 접속.

**비용**: 발화 호출에 출력 필드로 얹으면 +0콜, 별도 호출이면 4에이전트·3라운드 기준 +12콜/run. (미정 — 템플릿 작업 때 확정)

**예약값 (문서에만 등재, 구현 안 함)**:
- *공용 게시판* — 중앙 요약 1개를 전원 공유(회사 오케스트레이터 직접 모사). 평평한 조건이라 취합 실험에는 부적합(전원이 같은 텍스트를 받으면 실패 귀속 불능 + 수렴 강제) — 회사 구조 재현이 필요해질 때만.
- *전달문(전화 게임)* — 보내는 쪽이 자기 발언을 500자로 압축해 송신. 압축 자리를 두 군데 동시에 열지 않기 위해 보류.

### 2-3. 입장·성격 — 우리 소유 파일 필요

저자 프롬프트·성격 문구는 라이선스 보류로 **DelibTrace 원본 저장소에서 직접 읽는 구조**라 거기에 추가할 수 없다. 무입장 템플릿과 우리 성격 문구는 **우리 리포 소유 파일**로 신설하고, 로더에 로컬 경로를 연다. 새 템플릿은 등록제(v0.3 경계 조항 A-3)에 따라 재조립 규칙과 함께 등록 → `validate --deep` 통과.

부수 효과: 우리 소유 템플릿이므로 라이선스 문제 없음.

### 2-4. 정보 나누기 — 생성기 요건

순수 함수 · LLM 호출 0 · 겹침도 k 조정 가능. 추가 요건(히든 프로필 온전성 검사 7/28의 실측 결과): **요건 쌍 쪼개기** — 한 에이전트가 한 요건의 양쪽(A측·B측)을 통째로 쥐면 혼자 비교가 완결되어 단독 기준선이 75%까지 올라간다. 각 에이전트가 서로 다른 요건의 조각을 갖도록 배분해 단독 기준선을 우연 수준(≈50%)으로 낮춘다.

## 3. 조건 이름 규칙 (제안 — 이름 스타일 민옥 결정 대기)

- **문서·대화**: 한글 이름 ("온전 대화", "수첩 대화")
- **기록**(`condition` 필드·파일명): 영문 슬러그 (`talk-full`, `talk-note`)
- 슬러그 → 설정 좌표 대응표는 이 문서가 정본. 요한 님 `condition` 라벨(v0.3)의 어휘 공급원.

## 4. 실행할 조합 후보 (지위: 제안 — 어느 조합을 돌릴지는 민옥 결정)

**코어 5종 — "취합의 5단 스토리".** 각 조건이 질문 하나씩을 담당하고, 인접 조건의 차이가 주장 하나씩을 만든다.

| # | 이름(가칭) | 설정 좌표 | 묻는 질문 | 상태 |
|---|---|---|---|---|
| 1 | 천장 `ceiling` | 단독 1인 · 12팩트 전부 | 혼자 다 알면 푸는가 | ✅ 완료 (10/10) |
| 2 | 단독 기준선 `solo` | 단독 1인 · 관점별 배분 | 나눠 가지면 혼자선 못 푸는가 | ⚠ 배분 v2로 재실행 필요 |
| 3 | 온전 대화 `talk-full` | 4에이전트 · 직전만 · 수첩 없음 · 무입장 | 대화가 정보 격차를 메우는가 | 무입장 템플릿 대기 |
| 4 | 수첩 대화 `talk-note` | 3 + **개인 수첩 500자** | 기억이 깎이면 취합이 무너지는가 | 수첩 구현 대기 |
| 5 | 수첩+장부 `talk-note-ledger` | 4 + 자동 재주입 | 깎이는 기억을 장부가 보완하는가 | 4 위에 스위치만 |

읽는 법: 1↔2 = 눈금(취합이 필요한 상황 증명) / 2→3 = 취합의 몫 / 3→4 = 기억 손실의 해악 / 4→5 = 장부의 가치.

채점: 최종 결론이 정답인가 (JSON 이진 파싱 — **LLM judge 불사용**). 7/29 발견된 채점기 비일관성이 코어 5종에는 구조적으로 들어오지 않는다. 팩트 생존을 부지표로 얹는 순간 다시 들어오므로, 부지표 채택 시 별도 결정 필요.

**확장 2종 (선택 — 둘 다 yaml 한 줄로 지금 실행 가능)**:

| 이름(가칭) | 설정 | 묻는 질문 | 근거 |
|---|---|---|---|
| 장기전 `long` | 온전 대화 + 10라운드 | 3라운드가 전부인가 시작인가 | 요한 7/28 제안 — "3라운드 절단" 비판의 자기 적용 |
| 일렬 `line` | 온전 대화 + 일렬 연결 | 토론이 릴레이 전달보다 나은가 | 민옥 7/25 문제 재설정(A2A 위상 비교). 코드 기구현 |

## 5. 오늘 확정된 것 (민옥 7/29 구두 확정 — 보드 결정 로그 등재 예정)

1. 조건 어휘를 "사다리"에서 "설정 조합"으로 전환. 팀 용어는 일상어 원칙.
2. 연결 모양: 전원 연결 기본 (일렬은 비교용으로 보존).
3. 입장: 찬/반/없음 3값 — 무입장 템플릿 신설.
4. 성격: 직접 추가 가능하게 + 에이전트별 지정 (우리 소유 성격 파일 신설).
5. 정보 나누기: 생성기 신설 (직접 조정 가능하게).
6. **장부: 끔/자동재주입 두 값으로 동결. v1·v2는 만들지 않는다.** (원안의 Fact Ledger 사다리 종료 — 7/28 과녁 전환의 귀결)
7. 손실 모델링의 자리: 채널이 아니라 **기억** — 개인 수첩 신설. 수첩 갱신은 라운드 다이제스트가 아니라 자기 판단의 선별.

## 6. 이 문서가 풀어주는 대기 항목

- 요한 측 `condition` 라벨 (7/27 제안 — "민옥 님 조건 사다리와 어휘 통일" 대기) → §3 슬러그가 어휘 공급원.
- template 등록 (A-3) → §2-3 무입장 템플릿·§2-2 수첩 템플릿이 첫 등록 대상.
- 뷰어 쌍 비교 축 ③ (아키텍처 변주 표시) → §4 조합 이름으로 표시 가능.
- **작업 경계 재조정 예고 이행**: 사다리(→설정 조합) 확정 시 debate_engine 작업 경계를 요한 님과 재조정하기로 한 예고(민옥 7/28)가 이 문서로 발동된다.
