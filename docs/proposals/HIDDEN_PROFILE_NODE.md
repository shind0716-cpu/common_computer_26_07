## 0. 이 문서가 정하는 것

민옥 측 히든 프로필 시나리오(`issue_hire`)는 **결과 변수가 다르다** — 팩트 생존률(FAR)이
아니라 **정답 여부**다. 그래서 `judgment` 산출물이 없고, judgment 위에 선 현행 뷰어 3면
(두 판·대조·전기)은 이 run 을 열지 못한다. **버그가 아니라 측정 체계가 다른 것이다.**

이 문서는 그 트랙을 볼 노드의 **계약과 금지**를 구현 전에 고정한다. 구현 착수 여부·시점은
정하지 않는다(장래 목표).

---

## 1. 왜 새 노드인가 — 두 트랙의 대조

| | 팩트 생존 트랙 | 히든 프로필 트랙 |
|---|---|---|
| 결과 변수 | FAR(팩트가 남았나) | **정답 여부**(`final_poll` vs 정답) |
| 판정 경유 | 전량 judge 출력 | **정답 대조는 judge 0** |
| 압축의 부호 | **실패**(CLAUDE.md 규칙 5) | **해야 하는 일** |
| `note_update` | 접근 창이 집계를 멈추는 사유(정의 밖) | **관측 대상 그 자체** |
| 축 | 팩트 × 라운드 | **에이전트 × 라운드** |

마지막 줄이 화면을 새로 내는 이유다. 압축은 팩트가 아니라 **사람 단위**로 일어난다 —
`pair.html` 을 고쳐 쓰지 않는다.

**부호가 뒤집히는 것이 이 트랙의 핵심 위험이다.** 생존 트랙의 계기·문면은 "줄어든 것 = 손실"을
전제로 쓰였다. 여기서는 줄어든 것이 목적일 수 있다. 그러므로 **이 노드는 줄어든 것을 손실이라
부르지 않는다**(§5-3).

## 2. 재료 — 이미 있는 것만 쓴다

```
data/issues/issue_hire.json._note          정답(유지완) · 함정 설계 서술
data/facts/facts_issue_hire.json           share · favors · requirement · apparent
data/debates/debate_issue_hire_*.jsonl     utterance · note_update · final_poll · run_meta · seating
data/assignments/assignment_issue_hire.json 누가 어느 미공유 팩트를 쥐었나
```

⚠ **정답이 지금 `_note` 안의 자연어 문장에 있다**(`"정답=유지완(요건 3/4 충족…)"`). 계기가
자연어를 파싱해 정답을 뽑는 것은 금지한다(§5-2). 기계가 읽을 자리가 필요하면 **민옥 측에
필드 신설을 요청**하고, 그 전까지 이 노드는 정답을 **호출자에게 인자로 받는다**.

---

## 3. 계기 계약 — `modules/hidden_profile.py` (신설 예정)

순수 함수만. 파일 쓰기 0 · LLM 0 · 판정 0. 기존 계기 관례(`survival`·`crossrun`) 계승.

### 3-1. `outcome(events, *, answer: str) -> dict`

`final_poll` 이벤트를 좌표로 옮긴다. **판정 없음** — `response_text` 의 JSON 을 그대로 읽는다.

```python
{
  "answer": "유지완",                       # 호출자가 준 값. 계기가 추론하지 않는다
  "picks": [{"agent_id", "round", "recommend", "correct": bool, "parse_ok": bool}],
  "n_agents": int, "n_correct": int,       # 개수. 비율은 내지 않는다(§5-1)
}
```

`parse_ok=False`(파싱 실패)를 **정답도 오답도 아닌 제3의 값**으로 남긴다. 오답으로 세면
파싱 실패율이 정답률에 조용히 섞인다.

### 3-2. `fact_trace(events, assignment, facts_doc) -> list[dict]`

미공유 팩트마다 **보유자·등장 좌표**를 놓는다.

```python
{
  "fact_id", "share", "favors", "requirement", "apparent",   # 설계값 그대로 통과
  "holders": [agent_id, ...],                                 # 배분표에서
  "utterance_coords": [{"round", "agent_id"}, ...],           # ← 호출자가 넣는다(§3-4)
}
```

### 3-3. `note_trace(events) -> list[dict]`

에이전트별 수첩 판본을 **원문 그대로** 좌표에 건다.

```python
{
  "agent_id", "round", "source",           # note_update.source (dedicated/utterance/intervention)
  "note_text": str,                        # 원문 전량. 요약·발췌 금지
  "n_chars": int,                          # 길이만. "얼마나 줄었나"는 화면이 뺀다
}
```

### 3-4. 등장 좌표는 계기가 만들지 않는다

"이 팩트가 이 발화에 나왔나"는 **판정**이다. 계기는 그 판정을 하지 않고 **좌표를 받는다**
(`utterance_coords`). 지금 가능한 공급원은 둘뿐이며 둘 다 호출자 책임이다:

- **사람 라벨** — 1급. 이 트랙의 정본 경로.
- **judge 출력** — 생존 트랙의 `agents_mentioning` 을 빌려 오는 경우. 그러면 그 값이
  판정 매개임을 화면이 밝혀야 한다(생존 트랙에서 쓰던 `evidence` 등급과 같은 대접).

문자열/근접도 자동 추출은 **금지**(§5-2).

## 4. 화면 — 두 층, 각각 혼자 선다

**1층 · 정답 대조** — `outcome()` 만 쓴다. 판정 0. 지금 데이터로 즉시 성립.
run 별로 에이전트 선택과 정답 일치, 조건(`run_meta.settings`)을 나란히.

**2층 · 수첩 판본 격자** — 에이전트 × 라운드. 칸을 누르면 **그 판본 원문 전량**이 열리고,
같은 자리에 **그 사람이 그 라운드에 받은 입력**(`/api/inputs` 재조립분)을 나란히 놓는다.

2층의 목적은 한 줄로 고정한다: **수첩에만 있고 입력에는 없던 문장을 사람이 찾을 수 있게 하는
것.** 계기는 그 문장을 찾아 주지 않는다(§5-2). 자리만 만든다.

**1층은 2층 없이도 쓸모가 있고, 2층은 3층 없이도 쓸모가 있어야 한다.** 이 조건을 만족하지
못하는 층은 짓지 않는다.

## 5. 절대 금지 (구현 지시서 맨 앞에 복사할 것)

1. **새 비율·점수를 정의하지 마라.** 정답은 **개수**로 낸다(`n_correct/n_agents` 를 계기가
   나눠서 내지 않는다). 비율은 조건 의존인데 화면은 조건 비의존처럼 싣는다
   (2026-07-30 용어층·범례 폐기 2건의 원인).
2. **수첩·발화에서 팩트를 자동 추출하지 마라.** 문자열 대조는 어휘 치환만으로 붕괴한다
   (`SCHEMA_v0.3_NOTE_SLOT §4`, H2 실측 0.641). 근접도도 안 된다 — 시선 유도로도 쓰지 않는다.
   이 트랙은 압축을 재는데, 압축은 **표현이 바뀌는 것**이라 문자열 대조가 가장 크게 틀리는 곳이다.
3. **줄어든 것을 "손실"이라 부르지 마라.** 계기는 `n_chars` 와 판본 원문만 낸다. "버렸다 /
   필요 없어 뺐다"의 구분은 `requirement`·`favors` 값을 나란히 보고 **사람이** 정한다.
4. **임계값을 만들지 마라.** "등장 1회 이하 = 취합 실패" 같은 선을 긋지 않는다. 횟수를 그대로
   적는다.
5. **분모를 먼저 그려라.** 기본 화면은 미공유 팩트 **전량** 격자다. 플래그·정렬은 그 위에
   얹고, 기본값은 전량 표시다(대조 화면의 "볼 값어치 있는 칸만" 체크박스와 같은 방식).
6. **정답을 자연어에서 파싱하지 마라**(§2).

## 6. 완료 판정 — "필드가 같은 줄에 뜬다"로 쓴다

"사람이 X 를 읽을 수 있다"로 쓰지 않는다(데이터가 바뀌면 무너진다 — 2026-07-30 교훈).

- 1층: run 한 줄에 `recommend` · `correct` · `parse_ok` · `run_meta.settings` 가 함께 뜬다.
- 2층: 칸 하나에 `note_text` 전량과 그 좌표의 입력 전문이 **같은 화면에** 뜬다.
- 미공유 팩트 격자는 **전량**이 기본이며, 등장 0회인 팩트도 행을 차지한다.
- `parse_ok=False` 인 폴링이 정답·오답 어느 쪽 개수에도 들어가지 않는다.

## 7. 기각한 대안

- **생존 트랙 화면 재사용** — 축이 다르다(팩트 vs 에이전트). 억지로 얹으면 두 트랙의 문면이
  섞이고, 그게 이번에 폐기한 용어층 사고의 형태다.
- **히든 프로필 run 에 judge 를 돌려 judgment 를 만들기** — 측정 체계가 다른데 산출물 모양을
  맞추려 비용을 태우는 것이다(예상 144콜/run). 정답 대조는 judge 없이 성립한다.
- **취합 판정을 1층과 함께 짓기** — 1층은 판정 0이고 2층은 판정 의존이다. 함께 지으면 1층의
  확실함이 2층의 불확실함에 물든다.

## 8. 밑그림 관측 (2026-07-30 · `gpt001`·`테스트`·`smoke_gpt` 3판을 사람이 읽은 것)

**지위 등급을 함께 적는다. 이 절은 근거가 아니라 계기 설계의 재료다.**

| 등급 | 관측 | 이 판에서 말할 수 있는 것 |
|---|---|---|
| **존재 증명** | `agent_2` r0 수첩에 입력에 없던 문장이 사실처럼 적혔고(*"한도영… HANBIT 유지보수 실무 적합성이 높고"*), r1 발화에서 본인이 충돌을 발견해 정정했다 | **압축이 오염을 만들 수 있다**는 것이 한 사례로 증명됨. 빈도는 모름 |
| **존재 증명** | `테스트` run 에서 `fact_07` 등장 0회 — 보유자가 끝까지 말하지 않음 | **미공유 정보가 통째로 안 나오는 run 이 실재**함 |
| **관측(단판)** | `gpt001` 은 미공유 8개가 전부 r0 에 등장했으나 이후 인용이 편중(처우 9·10회 vs `fact_07` 1회), 정답은 요건 4축 중 2축(기술·처우)만으로 도출 | 이 판에서 그랬다. 일반화 불가 |
| **인상** | 반증 카드가 먼저 버려진다 · 미공유 누락이 정답률을 낮춘다 | **가설이라 부르기도 이르다.** 다른 데이터로 세워야 한다(같은 판으로 세우고 같은 판으로 확인하면 자기 순환) |
| **설계상 참** | 미공유 6:2(유지완:한도영) · 정답=유지완 · 요건 4축 | run 무관하게 참(설계값) |

설계에서 오는 좌표(`share`·`favors`·`requirement`)는 **조건 비의존**이라 계기가 그대로 실어도
되고, 관측에서 오는 값(등장 횟수·수첩 길이)은 **조건 의존**이라 조건과 함께 실어야 한다.

이 절이 계기에 요구하는 것은 "무엇을 재라"가 아니라 **무엇을 못 보게 만들지 마라**이다:
① 첫 등장만으로는 부족하다(살아남은 횟수) ② 수첩 판본 사이의 차이 ③ 수첩에만 있고 입력에는
없던 문장.
