**확정일 2026-07-29 · 요한 측 소관 확정(규약 7) · 이 문서는 사전고정이며 고정 이후 변경은 append 전용**

> 계기: 민옥 측 「실험 설정 사전 v0」(2026-07-29)의 **개인 수첩 신설**.
> 절차 전례: `FACTCLOCK_PREREG`(ff9f7de) · `P3_TRANSMISSION_DESIGN`(a70470d) — **구현 전 단독 커밋.**
> 성격: v0.3 방식 계승 — **추가만, 기존 이벤트·필드 변경 0 · 삭제 0.** 구 로그 전부 호환.

## 0. 이 문서가 정하는 것

수첩은 슬롯 하나 추가가 아니다. 두 가지를 동시에 건드린다.

1. **재조립 계약** — `--deep`의 sha256 검증이 성립하려면 슬롯 참조가 **불변 기록**을 가리켜야 하는데, 수첩만 라운드마다 내용이 바뀌는 가변 상태다.
2. **A-2 예약 조항** — 수첩 경유 도달은 v0.3 개정 1이 "도입 시 별도 정의를 강제한다"고 예약해 둔 **매개 노출**의 첫 사례다.

§1~§3이 1을, §4가 2를 정한다. §4가 이 문서의 본체다.

---

## 1. 왜 참조에 시점이 필요한가

`--deep`의 계약은 하나다.

> 조립 명세(`prompt_assembly`) + 명세가 가리키는 기록 → **재조립 텍스트의 sha256 == `prompt_hash`**

현행 슬롯이 가리키는 것은 전부 불변 기록이다.

| 슬롯 | 대상 | 불변성 |
|---|---|---|
| `assigned_fact_ids` | facts json | 정적 |
| `others=[{round, agent_id}]` | 저장된 발화 | 로그 불변 |
| `previous` | 자기 직전 발화 | 로그 불변 |
| `inject` | `ledger_inject.injected_text` | 원문 전량 저장(A-1) |

수첩은 **같은 에이전트의 같은 "수첩"이 라운드마다 내용이 다르다.** 참조에 시점이 없으면 재조립이 어느 판본을 집을지 정할 수 없고, 계약이 그 자리에서 무너진다.

## 2. 추가 ① — 이벤트 `note_update`

수첩 텍스트는 다른 어떤 기록에서도 복원 불가능하다(모델이 그 자리에서 쓴 것). **A-1(복원 불가 텍스트 전문 저장 일반 조항)의 두 번째 사례**이며 `injected_text`와 같은 대접을 받는다.

```
event:      note_update
run_id:     str
ts:         str (iso8601)
agent_id:   str
round:      int          # 이 갱신이 일어난 라운드 (= 이 라운드 끝에 쓴 것)
note_text:  str          # 원문 전량. 요약·절단 금지
origin:     "model" | "intervention"      # §6
source:     "utterance" | "dedicated"     # §5
```

- 수첩의 "현재 값"은 저장하지 않는다. **사건이 1급, 상태는 뷰**(v0.3 본문 원칙).
- 갱신이 없었던 라운드는 이벤트를 만들지 않는다 — 이벤트 부재가 곧 미갱신이다.

## 3. 추가 ② — `prompt_assembly.note`

```
note: { agent_id: str, source_round: int }  |  null
```

**`source_round`는 "직전 라운드"로 계산하지 않고 실제로 사용한 판본의 라운드를 그대로 적는다.**
사유: ⓐ round 0에는 수첩이 없다(→ `null`) ⓑ 갱신이 실패·생략된 라운드가 생기면 `r−1` 규칙이 즉시 깨진다. 계산 규칙을 계약에 넣으면 예외마다 계약을 고쳐야 한다.

`agent_id`는 발화자와 같아 중복이지만 명시한다 — 검증이 자기참조 없이 성립하고, 이후 공용 수첩·타인 수첩 열람 같은 변형이 와도 슬롯 모양을 바꾸지 않아도 된다.

**재조립 규칙**

- `note` 슬롯 → `note_update(run_id, agent_id, source_round).note_text`를 **그대로** 삽입.
- `null`이면 슬롯 블록 **자체를 생략**한다. 빈 문자열 삽입과 다른 해시가 나오므로 둘을 섞으면 안 된다.
- 참조 대상 `note_update`가 없으면 `--deep`은 **실패**로 처리한다(조용한 통과 금지).

## 4. ★ A-2 발동 — 매개 노출 정의

v0.3 개정 1 A-2:

> 노출은 **직접 노출**만 정의한다. 매개 노출(파생 텍스트 경유)은 **예약 개념**이며, 도입 시 별도 정의를 강제한다.

**수첩이 그 첫 사례다.** 팩트 f가 라운드 r에 에이전트 i에게 닿는 경로가 "이웃의 발화"가 아니라 "이전 라운드를 i가 압축해 넣은 자기 수첩"이 된다.

정의를 미룰 때의 결과: 에이전트가 **직접 노출 기록 없이** 팩트를 발화하고, 현행 P3 층1은 이를 `prior_suspect`(사전지식 의심)로 분류한다. 실제로는 사전지식이 아니라 자기 기억이다. **분모가 조용히 틀린다.**

### 검토한 대안과 기각 사유

| 안 | 기각 사유 |
|---|---|
| 수첩 텍스트에 judge를 돌려 팩트 포함 판정 | 판정기를 되돌린다. 게다가 7/29 계기 점검상 **압축 텍스트가 판정기가 가장 못 잡는 형태**다(요지압축 검출 41.7%) |
| 팩트 원문 문자열 대조 | 어휘만 치환해도 원문 근접도가 0.641로 떨어진다(H2 실측) → **과소 계상.** 지표 불가, 진단용 사이드카까지 |

### 확정 문면

> **수첩 경유 도달은 매개 노출로 분류하며, 직접 노출과 합산하지 않는다.**
> **수첩이 켜진 조건(`memory: note`)에서 P3 층1 지표(전달 폭 B · TSR · 획득 hazard)는 산출하지 않는다.**
> 매개 노출의 정량 정의는 **판정 없이 성립하는 방법이 나올 때까지 예약을 유지**한다.

적용 범위 주: 코어 5종은 최종 결론 정답 여부로 채점(LLM judge 불사용)하므로 층1 지표를 필요로 하지 않는다. 층1은 수첩 없는 조건(논문 재현 = Track R 포함)에서 종전대로 유효하다.

## 5. 수첩 갱신 호출 방식 — 계약 부담 (구현 판단은 민옥 소관)

| 방식 | 계약 부담 |
|---|---|
| **발화 호출에 필드로 얹음** (+0콜) | `note_text`를 응답에서 파싱해야 하므로 **파싱 규칙이 계약**이 된다. 규칙 변경 시 구 로그가 다르게 재파싱되어 과거 수치가 소리 없이 변한다 → `NOTE_PARSE_VER` 필수(`JUDGE_PROMPT_VER`와 같은 이유). 부수: 갱신이 발화와 한 호출에 묶여 "남길 것 선택"이 발화 전략에 오염될 수 있다 |
| **별도 호출** (+에이전트수/run) | 독립 LLM 호출이므로 **그 호출의 입력도 `prompt_assembly`로 기록**되어야 한다. 아니면 "입력이 기록되지 않은 LLM 호출"이 생기며, 그것이 v0.3이 없애려던 구멍이다 → template 등록제(A-3)에 `note_update` template을 추가 등록하고 재조립 규칙도 함께 등록 |

`note_update.source` 필드가 어느 방식으로 생성됐는지를 기록한다. 두 방식이 한 run 안에 섞이는 것은 금지한다.

## 6. 개입 run 표시

민옥 측 설계 원칙 4(수첩에서 특정 팩트를 지우고 재실행하는 인과 개입)는 **저장된 수첩을 사람이 고쳐 넣는 것**이다. "개입 run은 본실험 수치와 섞지 않는다"는 **습관이 아니라 필드여야** 한다 — 로그만 보고 구분 가능해야 한다.

- `note_update.origin: "intervention"` 으로 표시.
- 집계 코드는 `intervention`을 기본 제외한다.
- 개입 run은 `condition`도 별도로 단다.

## 7. 설정 좌표 — 계약이 요구하는 분리

- `memory: none | note` 와 `note_budget: 500`(기본값)을 **두 칸으로 분리**한다. 값 안에 예산을 박으면(예: "개인 수첩 500자") 250/1000 비교가 조건 이름 밖으로 밀려나고, 결국 run 이름에 인코딩된다 — v0.3 `condition` 라벨이 없애려던 문제의 재발이다.
- `window: rolling | cumulative`(받은 발화의 창, A-3)와 `memory`(수첩)는 **직교하는 슬롯**이다. 수첩을 창 정책 값으로 넣지 않는다. A-3의 창 정책 어휘는 수첩을 포함하지 않는다.
- `condition`(사람용 슬러그)은 **좌표의 별명이지 좌표 자체가 아니다.** run 메타에 슬러그와 설정 좌표 맵을 함께 둔다.

## 8. 불변 (재확인)

- 기존 이벤트·필드 **변경 0 · 삭제 0.** 추가는 `note_update` 1종 + `prompt_assembly.note` 1필드.
- 구 로그 전부 호환 — `note` 슬롯이 없는 로그는 `--deep`이 종전대로 통과(v0.2 로그 생략 통과와 동일 처리).
- judge 확정 사양 무관·불가침.
- 이 문서 자체는 코드 0줄 변경. 추가 LLM 호출은 §5에서 별도 호출을 택할 때만 발생하며, 계약 자체는 0콜.

## 9. 구현 경계

경계는 파일 단위가 아니라 **"계약 먼저, 구현 그 위"**로 잡는다. `assemble_initial/continue`는 엔진·검증기 **단일 소스**이므로 파일로 자르면 둘이 갈라져 재조립 드리프트가 난다.

| 순서 | 일 | 주체 |
|---|---|---|
| ① | 본 문서(슬롯 명세·재조립 규칙·A-2 정의·`origin`·좌표 분리) | 요한 — **이 커밋** |
| ② | template 등록 + `note_update` 방출 + 조립 함수 슬롯 주입 | 민옥(`debate_engine` 소유). 이관 시 요한이 파일럿 방식으로 |
| ③ | `validate --deep` 수첩 슬롯 재조립 검증 | 요한 |

②가 없으면 ③은 검증할 대상이 없다. ①은 착수 규칙(팀원 1인 이상 동의 시 즉시 착수, 민옥 확정 7/29)에 따라 선행한다.
