# 팩트 기준 시계(fact-clock) — 판별 기준 사전 고정 (Pre-registration v0.1)

> **이 기준은 정식 재실행(Sonnet+temp0) 데이터 생성 전에 커밋되었다.**
> 커밋 시각: **2026-07-22T07:46:12Z (UTC) / 2026-07-22 16:46 KST**.
>
> 배경: 현행 P2(`modules/survival.py`)는 **전역 시계**로 소실을 잰다 — 모든 팩트가 stage
> 0,1,2…를 공유한다. 3분할이면 전이가 2개뿐이라 구간 경계가 임의적이다(리더 지적). 이 문서는
> 각 팩트의 **도입 시점(첫 생존 stage)을 t=0으로 정렬**해 "도입 후 경과 나이(age)별 생존"을
> 재는 **entry-time alignment**(생존분석 정석)의 해석 기준을, **데이터를 보기 전에** 고정한다.
> 채점(judgment)은 그대로 재사용하고 분석 축만 재정렬하므로 추가 채점 비용은 0이다.

근거 코드: `modules/survival.py`의 기존 헬퍼(`_sorted_stages`·`_status_map`)와 잣대
`judge.SURVIVING`을 재사용한다. 신규 파일이며 기존 코드·문서를 수정하지 않는다.

---

## 1. 정의 (확정)

- **생존 잣대**: `judge.SURVIVING`을 그대로 import(P2와 동일 단일 소스). 현재 잠정
  `{mentioned, accepted}`이며, 정식 judge v0는 이진 판정이라 실질 `{mentioned}`이다. 이 문서의
  판별은 동일 잣대를 age 축에서 상대 비교하므로 잣대 절대값 변경에 견고하다.
- **도입(entry)** = 팩트의 **첫 SURVIVING stage**. stage는 정렬된 순서의 **위치 인덱스**로만
  쓴다(stage 절대값이 0-기반이든 아니든 무관, 순서만 사용). `age t` = 도입 이후 t번째 위치.
  age 0 = 도입 stage 그 자체(정의상 생존).
- **미도입 팩트** = 어떤 stage에서도 SURVIVING이 아닌 팩트. **fact-clock 모집단에서 제외**하고
  `n_never_introduced`로 **별도 카운트**만 보고한다(hazard 계산에 넣지 않는다).
- 입력 계약은 P2와 동일: `stages[].facts[].{fact_id, status}`만 의존, 매 stage는 전 팩트
  완전 스냅샷. (레코드 부재는 방어적으로 비생존으로 취급.)

## 2. age t hazard — 분모/분자와 우측 검열

각 팩트를 도입 정렬해 불리언 열 `surv_flags[0..M]`을 만든다.
- `M`(관측 가능한 최대 age) = `(stage 수 − 1) − 도입 위치`. 도입이 늦을수록 M이 작다.
- `surv_flags[0] = True`(도입 = 생존). `surv_flags[a]` = 위치 `도입+a`의 status ∈ SURVIVING.

**관측 창**: 팩트는 age `0..M`만 관측 가능하다. age `> M`은 데이터가 없다(**우측 검열**).

### 사건 판정 `_fact_event(surv_flags, w)` (의사코드)
```
scan t = 1..M:
  if surv_flags[t] == False:
     run = t 부터 연속 비생존 길이
     if run >= w+1:                 -> 사망(death), 사망 age = t        # 치명 런의 시작점
     elif (t + run - 1) == M:       -> 검열(censored), age = t - 1      # 경계에 걸린 미확정 침묵
     else:                          -> 브릿지(관용): t = t + run 로 건너뛰고 계속  # (w>=1)
  else:
     t += 1
루프가 끝까지 사망/검열 없이 지나면 -> 검열(censored), age = M          # 관측 끝까지 생존
```
→ 각 팩트는 정확히 하나의 사건을 갖는다: `(death, age)` 또는 `(censored, age)`.

### 생명표(pooled — 여러 judgment/팩트를 age별로 합산)
```
at_risk(t) = #{ event_age >= t }              # t 진입 시점에 아직 관측 중이고 안 죽은 팩트
deaths(t)  = #{ event == death 이고 age == t }
hazard(t)  = deaths(t) / at_risk(t)            # at_risk(t) == 0 이면 None
KM 생존 S(t) = Π_{u<=t} (1 - hazard(u))         # hazard None 인 age 는 건너뜀, S(0)=1
```

**검열 규칙(요한 설계 원칙 1의 형식화)**: age t의 hazard **분모 = "관측 창 ≥ t(즉 도입위치+t
≤ 마지막 stage)이면서 age t−1까지 생존한 팩트"**로 한정한다. 늦게 도입돼 관측 창이 짧은 팩트는
자기 관측 범위(M)를 넘는 age의 분모에서 **자동 제외**된다 — 우측 검열. 극단: 마지막 stage에서
도입된 팩트는 M=0이라 age 0만 관측되고 age ≥ 1의 어떤 분모에도 들어가지 않는다.

## 3. 침묵 허용 폭 w (형식) — 설계 원칙 2

두 값을 **항상 나란히** 산출한다.

- **w = 0**: 비생존 즉시 사망(치명 런 길이 1 = w+1). 이후 재등장은 무시(이미 이탈).
- **w = 1**: 한 stage 침묵 뒤 **관측된 재등장**이면 사망으로 치지 않는다(브릿지). 연속 2회
  침묵(런 길이 2 = w+1)이면 사망이며, 사망 age는 **런의 시작점**이다. 마지막 age에 걸린 단일
  침묵은 재등장을 확인할 수 없으므로 **검열**(직전 생존 age)로 처리한다.

**경계 침묵 처리(모델링 결정, 명시)**: w=1에서 관측 경계에 걸린 미확정 단일 침묵은 **검열**한다
(사망으로 세지 않음). 이는 "한 stage 침묵은 관용한다"는 w=1의 정의와 일치한다. 대안(경계
침묵을 사망으로 계상 — judge의 '레코드 부재=소실' 보수 관례 계승)은 w=1 정의와 모순되어 채택하지
않는다. w=0에서는 이 문제가 없다(단일 침묵이 곧 사망).

## 4. 해석 기준표 (정식 재실행 데이터용 — 지금 고정)

정식 데이터에서 **age에 따른 hazard 패턴**이 아래 중 무엇이면 무엇을 지지하는지 미리 못박는다.

| age별 hazard 패턴 | 지지 해석 |
|---|---|
| **ⓐ age↑ → hazard↑** | 오래된 팩트일수록 위험 — 확립 단서의 **누적적 침식**. 숙의가 진행될수록 이미 정착한 사실을 버린다(수렴이 기존 사실을 밀어냄). |
| **ⓑ age↑ → hazard↓** | **초기 정착 실패가 주 사망** — 도입 직후 탈락이 대부분, 일단 며칠 살아남은 팩트는 안정적. 손실이 "진입 직후" 사건. |
| **ⓒ 평탄(age 무관 상수)** | **무기억(memoryless) 소실** — 팩트가 얼마나 오래 살았는지와 무관한 상수 hazard(랜덤 이탈). |

**전역 시계 교차 해석(한 줄)**: 전역 U자의 우측 팔(= 실재 손실, `UCURVE_RESULT_DEMO.md`)이
fact-clock에서 **ⓐ**로 재확인되면 "후반 손실 = 오래된 팩트의 누적 위험"으로 지지되고, **ⓑ**로
나오면 "전역 축 후반 상승은 실은 **늦게 도입된 팩트의 초기 정착 실패**가 전역 시계에 몰려 보인
진입시점 아티팩트"일 수 있어 전역 시계의 후반-실재-손실 해석을 재고한다.

## 5. w=0 / w=1 갈림 처리 규칙

w=0과 w=1이 서로 다른 결론(ⓐ/ⓑ/ⓒ)을 가리키면 **둘 다 보고하고 갈림 자체를 결과로 기술**한다
— **단일 결론을 강제하지 않는다.** 갈림은 곧 "재등장(순환 churn)이 hazard 패턴을 좌우한다"는
1급 발견이며, 그 사실을 결과의 핵심으로 적는다. 두 값이 같은 방향이면 결론이 재등장 민감도에
견고하다는 뜻으로 함께 기록한다.

## 6. 데모 실행 표기 규칙

`judgment_issue_mystery_observed_demo.json`(팀이 이미 결과를 본 데모)에 fact-clock을 돌리는
것은 허용하되, 산출물·보고에 반드시 **"탐색적(사전 고정 이후이나 데이터 기지) — 정식 판정은
Sonnet+temp0 재실행분에서"**를 명시한다. 정식 데이터 전 커밋(사전 고정)이 성립하는 대상은
**미래의 재실행분**이다. 데모 파일과 그 산출 JSON은 리포에 커밋하지 않는다.

## 7. 개정 v0.1.1 (2026-07-22, 사후 명시) — w=1 검열 사유 분리 보고

> **이 절은 탐색적 데모 실행 이후에 추가된 보고 규칙이다.** §4 해석 기준표(ⓐ/ⓑ/ⓒ)는 손대지
> 않는다(사후 변경 금지). 데이터를 본 뒤 추가한 것이므로 §4의 post-hoc 규칙에 따라 "사후"로
> 라벨링한다 — 해석 기준을 바꾸지 않고 결과를 **어떻게 표기할지만** 강화한다.

계기(리뷰 지적): w=1 에서 사망이 줄어드는 것을 "재등장(churn)"으로만 읽으면 위험하다. w=1 에서
사망이 사라지는 경로는 **두 가지**다.
- **churn(재등장 취소)** — 침묵 후 관측 창 안에서 실제로 재등장해 사망이 취소됨(`survived_to_end`).
- **관측창 부족 검열(terminal silence)** — 마지막 stage 근처에서 침묵이 시작돼 재등장을 확인할
  stage 자체가 없어 **기계적으로 검열**됨. 재등장이 확인된 게 아니라 **관측 불가**로 검열된 것.

특히 전역 시계에서 실재 손실로 잡힌 팩트(확립 후 종말부 탈락 = SS− 형태)는 fact-clock 에서
종말부 침묵이 되어 w=1 에서 사라지는 게 당연하다 — 이는 churn 발견과 **다른 기전**이다.

**보고 규칙(강제)**: w=1 결과를 보고할 때 반드시
1. 검열을 `survived_to_end`(진짜 생존)과 `terminal_silence`(관측창 부족)로 분해 게재하고,
2. w=0 사망이 w=1 에서 사라진 건을 `death_robust` / `churn_reappearance` /
   `artifact_terminal_silence` 로 분해(`w_divergence`) 게재한다.

"w=1 사망 감소 = churn" 이라는 단정은 **금지**한다. 갈림 판정(§5)은 이 분해를 본 뒤에 한다.

구현: `survival.fact_clock(...)["censored_breakdown"]`, `survival.w_divergence(...)`,
`survival.fact_clock_report(...)["w_divergence"]`.
