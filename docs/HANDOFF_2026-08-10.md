## 4. 논문에서 벗어나 있는 곳 (실측)

저자 코드와 한 줄씩 대조한 결과다. **코드가 아니라 조건 좌표가 갈려 있다.**

1. **관점 생성 단계가 통째로 없다.** 저자에겐 `perspective.py` 가 있고, 거기서 LLM 이
   팩트를 4개 부분집합으로 묶는다 — 저자의 "관점" = 팩트 부분집합 그 자체다.
   우리 `perspective` 는 실행에 영향 없는 **문자열 라벨**이고 프롬프트에 들어가지도 않는다.
2. **관점 쌍의 팩트가 다르다.** 저자는 같은 관점의 yes/no 두 발화자에게 **동일한 팩트**를
   준다. 우리 ESA 배분표는 4쌍 중 팩트가 같은 쌍이 **0개**다.
3. **발화 온도가 1.2 가 아니다.** 저자 상수는 1.2 인데 config 18개 중 1.2 는 5개뿐이고,
   `논문재현콜` 이라 이름 붙은 판이 **1.0** 으로 돌았다. 원인은 콘솔 기본값
   (`tools/console/app.py:362,568` 의 `debate_temperature: float = 1.0`) — **민옥 님 담당.**
4. **loader·extractor 가 없다.** DESIGN 의 7모듈 중 1·2번 미구현. 팩트 3개 파일 전부
   `created_by: "manual"` 이다.
5. **`evaluate_stance` 대응물이 없다.** 저자는 발화마다 입장도 판정한다. 우리 `stance` 는
   배분표에 적힌 지시값일 뿐 발화가 실제로 어느 쪽인지는 안 잰다.

## 5. 다음에 할 일 (우선순위)

**A. 모듈 3개 구현** — 사양은 `PAPER_REPRO_HANDOFF.md` §5. 순서가 강제된다:
```
loader(0콜) → extractor(3콜/건) → perspective 배분기(1콜/건)
```
관점 배분기는 팩트를 입력으로 받으므로 extractor 가 먼저다.

**B. 표본 — 순차 설계.** 추출은 150~200건(전 팔이 공유하는 1회 비용, 싸다).
발화·판정은 **먼저 15~20건만** 돌려 항목당 FAR 의 표준편차를 실측한 뒤 n 을 재계산한다.
지금은 그 편차를 모른다(이슈가 ESA 하나뿐이었다).

**C. 보드 게시** — 계약 §1′ 결정 로그, `llm.py` 무수정 방침, 프로브 결과.
`llm.py` 건은 남기지 않으면 다음 사람이 "왜 러너에서 상한을 올렸나"를 모른다.

**D. 확인 필요** — Scruples/RealNews 라이선스(`usage_approved` 가 `null` 이다),
원본 데이터셋을 리포에 넣을지, `news_raw.json` 의 질문 생성(이번 범위 밖).

## 7. 반드시 지킬 것

- **append-only** — 문서·WORKLOG 의 기존 줄을 고치지 않는다. 정정은 아래에 덧붙인다.
- **`SCHEMA.md` 는 끝까지 읽는다** — 제목은 v0.2 지만 본문 뒤쪽에 v0.3 확정분이 있다.
- **경로 하드코딩 금지** — `modules/paths.py` 만 쓴다.
- **LLM 응답은 원문 그대로 저장** — 요약해서 저장하는 것이 이 프로젝트가 연구하는 실패다.
- **남의 담당 파일을 고치지 않는다** — `modules/llm.py`·`judge.py`·`debate_engine.py`(동범),
  `assignment_gen.py`·`tools/console/`(민옥). 결함을 찾으면 직접 고치지 말고 인계한다.
- **조건 변경 = 새 yaml.** 기존 config 를 수정하지 않는다.
- **API 루프에는 호출 상한과 체크포인트를 반드시 넣는다.**
- **기존 `experiments/` 폴더를 수정하지 않는다** — 코드가 아니라 기록이다.

## 8. 오늘 밟은 함정 (같은 데 빠지지 말 것)

- **`LLMTruncated`** — 저자는 `max_tokens` 를 안 보내는데 우리 `llm.MAX_TOKENS=2048` 이
  강제된다. gpt-5 의 사고 토큰이 예산을 먹어 첫 호출부터 죽는다. 러너에서 8192 로 올린다.
- **파일럿과 팀 데이터가 다르다** — `experiments/mini_h2_pilot/data` 의 `issue_esa` 에는
  `question` 이 주입돼 있고 팀 `data/` 에는 없다. **두 뿌리가 다른 조건으로 돌고 있었다.**
- **근접도는 지표가 아니다** — 시선 유도용이다. 근접도가 높은데 판정에서 빠진 칸을 보고
  "판정기가 틀렸다"고 의심했으나, 저자 축으로 다시 재니 **두 축이 일치**했다(오경보).
- **문자열 대조로 팩트를 비교하지 말 것** — 팩트 텍스트는 재작성되므로 구조적으로 틀린다.
  개수·비율로 비교하고 나머지는 사람이 읽는다.
