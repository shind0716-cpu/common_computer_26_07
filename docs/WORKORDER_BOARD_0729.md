## 글 A — 판정기 감사 공유

### 담아야 할 것 (사실 + 운영 결과)

1. **검출률은 구체어 잔존의 함수** — 원문 100% / 어휘치환 100% / 요지압축 42% / 상위개념 22%
   (고정 사다리, 12팩트×3표). 구체 정보가 남아 있으면 어휘를 바꿔도 전건 잡히고, 구체가
   지워지는 순간 절반 이하로 떨어진다.
2. **재판정에서 발견이 뒤집힘** — `fact_car_04` s0가 원판정 False → 재판정 **5:0 True**.
   7/28에 "즉시 사망·4관문 연쇄 첫 실물"로 보고했던 사례다. `car_02` s3도 뒤집혀 resurgence
   1건 소멸.
3. **전체 불일치율은 낮다(7%)** — 같은 입력엔 판정기가 대체로 일관하다. 이걸 빼먹으면
   "판정기 못 믿는다"로 과장된다.
4. **팀에 직접 걸리는 것 2건**:
   - **다수결은 판정 기준의 모호함을 못 누른다.** 확정 사양 n=3은 호출 비결정성을 누르는
     장치이며, 세 표가 같은 이유로 같이 틀리면 무력하다. 사양 변경 제안이 아니라 **한계
     명시**다.
   - **패키지 B 지침에 들어갈 재료**: `fact_esa_03` 사례 — stage2 "집주인 허락 없이
     반입"(원문에 더 가까움)=unmentioned / stage3 "무단 반입"(더 축약)=mentioned. 라벨러가
     "축약을 어디까지 언급으로 볼 것인가"를 **먼저 정하지 않으면 사람끼리도 안 맞고 κ가
     의미를 못 갖는다.** 예시 문항으로 그대로 쓸 수 있다.

### 담지 말 것 (외부 리뷰 후로)

- **"전체 오류율이 낮아도 오류와 발견이 같은 경계면에 있으면 개별 발견의 신뢰도는 보장되지
  않는다"** — 이 방법론 주장은 아직 외부 검증 전이다. 근거가 "불안정 3팩트 ∩ 특이 관측
  4팩트 = 3"인데 n이 작아 우연 배제가 안 된다. 게시 후 정정하는 것보다 리뷰를 거치는 게 낫다.
  (외부 리뷰 패키지는 `docs/HANDOFF_EXTERNAL_REVIEW_0729.md` 별건.)
- 시간축 편향(축약↑→누락↑→측정 소실↑)도 같은 이유로 **"제기 수준"으로만**, 결론처럼 쓰지 말 것.

## 글 B — R3 안건

`docs/WORKING_RULES.md` R3 전문을 근거와 함께 옮기고, **팀 규칙으로 채택할지 묻는다.**

- 규칙: 음영·resurgence·경계 사례처럼 "발견"으로 부를 것은 **재판정 n≥3 통과 후에만** 보고서·
  보드·팀 메모리에 올린다. 통과 전 지위는 "미확인 관측".
- 근거: 7/28 보고 → 7/29 5:0 뒤집힘. 재판정 5표는 **5콜**이었다.
- 한정: 게이트를 통과했다고 "검증됨"이 되지 않는다. ground truth는 사람 라벨(패키지 B,
  κ≥0.60/0.80)의 몫이다.
- 지위: **제안**. 요한 측 작업 규칙으로는 이미 채택했고, 팀 적용은 보드 판단.

- **보드 양식**: 맨 위 사람용 세 줄(① 뭘 했나 ② 팀이 알아야 할 것 ③ 결정할 것), 각 항목에
  작성 주체·날짜, **근거 한 줄 필수**(규약 5).
- **append-only**(규약 1) — 기존 글 수정 금지, 새 항목으로.
- **확정은 사람만**(규약 3) — 두 글 다 **지위: 제안/공유**로. 게시 자체가 요한 문면 승인 사안.

  n=1)다. 가설 언어 금지, 톤은 "계기를 재봤더니 이렇게 보였다"까지.

  "재판정이 맞다"고 쓰면 안 된다.
