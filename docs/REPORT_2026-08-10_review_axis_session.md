## 0. 배경 한 문단 (이 프로젝트를 모르는 독자용)

AIFFEL 커먼컴퓨터 팀은 "AI 여럿이 토론하면 사실(팩트)이 사라진다"는 논문(실측: 대화 없음 19% vs
토론 후 68% 손실)을 비판적으로 재현하는 파이프라인을 만들고 있다. 8/10 저녁까지 모듈 구현
(추출기·배분기·접합 계층)과 첫 실호출(1차 트랜치 79콜 + 계기 교정 208콜 등 약 410콜)이
끝났고, 자체 멀티에이전트 코드 리뷰(PR#34, 인라인 14건)가 "변경 필요" 판정을 내린 상태에서
이 세션이 시작됐다. 이 세션의 산출: ① API 실비용 확인과 예산 재산정 ② 리뷰 14건 전건 처리
③ 핵심 실측치 검산 ④ 판정 축 확정(보드 게시) ⑤ PR 머지.

## 2. PR#34 리뷰 14건 처리 (차단 8·경고 6, 실호출 0)

처리 원칙(요한 승인 가드레일): 모든 리뷰 주장은 **수정 전에 직접 재현**, 증상이 아니라
불변식을 수정, 회귀 테스트는 리뷰 시나리오+변형. 리뷰 전제 오류도 1건 검증으로 걸러냄
(리뷰 "공개 저장소" 전제 → 실측 private).

### 2-1. 캐시 정체성 통일 (차단 5건의 공통 뿌리)
체크포인트가 tag만 보고 실행 좌표를 안 봐서, 조건이 바뀌어도 낡은 응답을 0콜 재사용하던
결함군. 수정: 캐시 행에 좌표(model·temperature·n·prompt_ver·prompt_sha256) 기록,
적중 시 대조 불일치 즉사, dry/live 파일 격리, 매 콜 append+flush, rehearse 재사용 관문
3종(debate config 지문·judgment 좌표·체크포인트 행). **기존 유료 원장 143행 오거부 0**
(재검증 완료 — 돈 다시 안 씀).

### 2-2. 부재≠소실 관철 (실험 결론을 건드리던 4건)
판정기 장애(parse_fail)가 "팩트 소실"로 계상되던 결함군 — 이 리포 자신의 원칙("부재는
모름이다")의 코드 위반. 수정: parse_fail 섞인 stage는 FAR 미산출(None)+coverage 기록,
전 행 실패 stage는 즉사, **빈 배열 매치는 정상 판정으로 구분**(pilot1 실측이 이 유형),
failed_parse의 배분기 전파, verify_bridge에 H9 완전성 게이트(manifest의 완료 주장 vs
실물 파일 대조, 설명 없는 누락 = 경성 실패).

### 2-3. 잔손 + 종결 폴더 방침
- validate에 §1′ `issue.question` 타입 검사(계약이 약속하고 구현이 누락됐던 것) + 테스트 3종.
- bridge stance `_note` 극성 문구 교정(계산 pro→NO인데 설명이 pro→yes로 반대).
- **종결 실험 폴더(judge_axis·structure_axis)는 코드 무수정** — 요한 방침
  "종결 러너는 증거물(수치의 알리바이), 수정하지 않고 결함을 append"에 따라 결함 4건
  기록 + 재사용 금지 표기. structure_axis 실측 산출물 무손상 확인 포함.
- L-2(원문 라이선스): 리포 private 실측, usage_approved=null 유지, (a)안 잠정
  (private 유지 + 내부 연구용 지위 명기) — README append.
- WORKLOG 232행 개행 복구(두 레코드가 붙은 형식 결함, 내용 무변경).

### 2-4. 검증 수치

## 3. pilot1 0콜 재집계 — 핵심 실측치 검산

핵심 질문: 어제 발견된 판정 축 분기(최종 FAR 우리 축 0.42 vs 저자 축 0.92)가
위 리뷰 결함의 오염이었는가?

- 방법: **판정 규칙을 실행 전에 커밋으로 고정**(`recheck_pilot1/PREREG.md` — R1~R3·G5,
  결과에 규칙을 맞추는 과적합 차단) 후, 보존 원문(콜 원장 64행)을 수정된 코드로 재처리.
- 결과: **R1 — 전건 일치.** 재파싱 불일치 0/32 · far_by_stage 전 stage 동일
  (0.0833/0.8333/1.0/0.9167) · stance 유지율 동일(1.0/0.375/0.625/0.5).
  극단값(stage2 FAR 1.0)은 원문 직접 확인 — gpt-5가 `{"matched_fact_ids": []}`를
  정상 반환한 것(파서 문제 아님).
- **결론: 축 분기는 리뷰 결함의 오염이 아니라 유효한 관찰. 축 확정 논의 재개 가능해짐.**

## 4. 결정: 판정 축 확정 (요한, 8/10)

**논문 재현 트랙의 FAR 판정 축 = 저자 축(발화×팩트목록, n=1). 효력은 논문 데이터 한정.**

- 근거 3개: ① 목적 정합 — 논문 수치(68% 손실)는 저자 축의 구성 개념이라 같은 잣대여야
  비교 성립 ② pilot1 실측 0.42 vs 0.92(검산 완료) — 축 선택이 헤드라인을 2배 이상 가름
  ③ 비용 — 건당 32콜 vs ~188콜(약 2.5배).
- 효력 경계: "저자 축이 더 옳다"가 아님(한국어 ESA에서는 양축 0.979 일치). 타 트랙·
  한국어 데이터는 우리 축 유지, 기존 산출물 소급 재판정 없음. 우리 축 부분 병행(3~4건)은
  별도 결정. judge 사양 고정(Sonnet·3표)의 변경 아님 — 별도 축 병존(`author_axis_n1` 각인).
- 게시: 노션 보드 결정 로그 등재 + 전문 하위 페이지
  (https://app.notion.com/p/3b80261412b0817ba665e4b62da25e81).
